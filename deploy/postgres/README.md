# deploy/postgres

PostgreSQL of Argos: the bundled image, the reference role SQL and the rules of the schema migrations
(design: `docs/13-storage-design.md` section 12 and 13.1; accounts: C-11 of `docs/02-architecture.md` section 13 and
ADR-0010 C-97).

| Path | Content |
|---|---|
| `image.properties` | The bundled PostgreSQL: exact 16.x version and multi-arch digest. Read by Compose (WO-40) and the server test environment. |
| `roles.sql` | Reference role SQL, run by the installer as a superuser (never by the server). WO-40 wires it into Compose and the tar installer. |

The schema itself is not here: it is the Flyway migrations of the server, `server/src/main/resources/db/pg`, which the
server applies at start (`POSTGRES_MIGRATION` phase) with the owner account.

## Accounts

| Role | Created by | Rights | Used by |
|---|---|---|---|
| owner (`argos`, `argos.postgres.owner.*`) | `roles.sql` | owns the database, the schema `argos` and every table | Flyway and the ClickHouse migration history, during the start only; the connections are closed at the end of each migration phase |
| `argos_app` (`argos.postgres.user`) | `roles.sql`; grants in `V001` | DML on the application tables; `audit_logs` INSERT and SELECT only (no UPDATE, DELETE, TRUNCATE); SELECT on `ch_schema_history`; USAGE on the id sequences; EXECUTE on `alert_events_maintain_partitions`; no DDL | server runtime (HikariCP pool) |
| `argos_audit` | `roles.sql`; grants in `V001` | EXECUTE on `audit_logs_maintain_partitions` only | audit partition retention job (WO-28) |
| `argos_backup` | `roles.sql`; grants in `V001` and in the partition function | SELECT on every table, partition and sequence of `argos` | `pg_dump` (13 section 10) |

`PUBLIC` has no right on the database (no CONNECT, no TEMP) and no CREATE on schema `public`. Every role is LOGIN without
SUPERUSER, CREATEDB, CREATEROLE, REPLICATION or BYPASSRLS. Passwords are generated by the installer (at least 12
characters, SEC-74) and passed to `roles.sql` as psql variables; the file contains none.

Compose note (WO-40): the official image makes `POSTGRES_USER` the bootstrap superuser. Use `POSTGRES_USER=postgres` and
let `roles.sql` create the non-superuser owner `argos`; with `POSTGRES_USER=argos` the owner stays a superuser.

## Migration files (`server/src/main/resources/db/pg`)

- Name `V<NNN>__<lower_snake>.sql`, numbers contiguous from `001` (ADR-0003 C-28; `checkFlywayNames` at build time,
  Flyway naming validation at start). No repeatable (`R__`), undo (`U`) or baseline (`B`) files.
- A released file never changes: Flyway refuses the start when the checksum of an applied file differs, when an
  applied version is missing from the server (a newer server applied it) or when a file is missing. A change is a new
  `V<next>` file from the work order that owns the table (ADR-0010 C-98).
- There are no default privileges. Every new table states its grants in the same file: `argos_app` the DML it needs
  (append-only tables: INSERT and SELECT), `argos_backup` SELECT, `argos_app` USAGE on new sequences.
- Flyway runs with `validateOnMigrate`, without baseline, `clean` disabled, without placeholder replacement and
  without out-of-order migrations.

## Partitioned tables

`alert_events` and `audit_logs` are partitioned by month of `ts` (UTC calendar months, partitions `<table>_pYYYYMM`,
no default partition). `V001` creates the current and the next two months, and every server start does the same
after Flyway (owner account, `POSTGRES_MIGRATION` phase). The partition job (WO-28) calls the functions daily, also to
drop expired months:

```sql
SELECT * FROM argos.audit_logs_maintain_partitions(2, now() - interval '365 days');    -- as argos_audit
SELECT * FROM argos.alert_events_maintain_partitions(2, now() - interval '365 days');  -- as argos_app
```

The first argument is the number of months to keep ahead (0..24), the second the drop limit: a partition is dropped
when its whole month ends at or before it (never the current month or later; NULL drops nothing). Until the job
exists (WO-28), a server that runs more than two months without a restart refuses audit and alert rows of the
uncovered month, and nothing is dropped.
