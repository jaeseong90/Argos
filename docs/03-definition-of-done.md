## 1. 왜 이 문서가 중요한가

구현을 Claude Code가 맡으면 사람의 일은 **"무엇이 끝난 상태인가"를 정의하고 검증하는 것**으로 바뀐다. 기준이 모호하면 AI는 그럴듯하지만 미완성인 결과를 "완료"로 보고한다. 오픈소스로 공개되면 외부 PR도 같은 기준을 통과해야 하므로, 기계가 검증하는 기준은 전부 CI가 대신할 수 있어야 한다. 그래서 모든 작업은 두 종류의 기준을 가진다.

1. **기계가 검증하는 기준**: 테스트, 빌드, 정적 분석, 보안 검사, 벤치마크. CI가 돌린다.
2. **사람이 검증하는 기준**: 수락 시나리오. 15분 안에 끝나야 한다.

둘 다 통과해야 DONE이다. 하나라도 빠지면 REVIEW 상태로 되돌린다.

## 2. 모든 작업 공통 DoD

작업 지시서(WO)마다 적용한다. Claude Code는 완료 보고에 아래 항목 각각의 근거를 적는다. 외부 PR은 CONTRIBUTING의 축약 체크리스트로 같은 내용을 확인한다.

- [ ] 코드가 빌드되고 해당 모듈의 검증 명령(`./gradlew :module:check`, `pnpm -C ui test`)이 통과한다.
- [ ] 새 기능마다 자동 테스트가 있고, 테스트가 WO의 수락 기준을 **직접** 검증한다.
- [ ] 기존 테스트가 전부 통과한다. 회귀 없음.
- [ ] 정적 분석 경고 0: Spotless 포맷, Error Prone, ESLint(`react/no-danger` 포함), `tsc --strict`, ArchUnit 규칙(Advice 금지 패턴).
- [ ] 변경이 문서에 반영됐다: 설정 항목은 설정 레퍼런스, API는 OpenAPI 스펙(허용 역할 `x-argos-role` 포함), 구조 변경은 02·설계 문서, 사용자 영향은 CHANGELOG(`Unreleased` 절, Keep a Changelog 형식).
- [ ] 공개 계약(설정 키·API·메트릭 이름·웹훅 페이로드·헤더·MDC 키)을 바꿨다면 CHANGELOG `Deprecated`/`Changed`와 업그레이드 가이드에 적었고, breaking이면 PR에 `breaking-change` 라벨을 달았다.
- [ ] 새로 수집하거나 저장하는 필드가 있으면 02 문서 데이터 분류표에 분류·기본값·보존·삭제 경로를 적었다. 개인정보 가능 필드는 기본 "수집 안 함 또는 마스킹"이다.
- [ ] 사용자·에이전트·외부 시스템에서 들어오는 모든 입력에 길이·개수 상한이 있고 초과 시 거부 동작이 테스트된다.
- [ ] 보안 영향이 있는 변경(인증·권한·전송·명령·수집 범위·마스킹)은 `docs/security/threat-model.md`를 갱신했다.
- [ ] 외부 네트워크 호출을 추가하지 않았다(알림 채널 등 운영자 설정 대상 제외).
- [ ] WO의 "범위 밖" 항목을 건드리지 않았다. 필요했다면 보고서에 제안만 남겼다.
- [ ] 완료 보고에 실행한 검증 명령과 출력 요약, 미해결 사항, 가정을 명시했다. 추측으로 "동작함"이라고 쓰지 않았다.
- [ ] 비밀값·토큰 하드코딩 없음(gitleaks 0건). 새 외부 의존성은 Apache-2.0 호환 허용 목록(01 문서 O-L03) 안이고 보고서에 라이선스를 적었다.
- [ ] 새 파일에 SPDX 헤더가 있고, 외부 코드를 차용했다면 원 저작권 헤더를 유지하고 출처·라이선스를 보고서와 `NOTICE`에 적었다.
- [ ] 에이전트 모듈에 의존성을 추가했다면 셰이딩 규칙·SBOM·버전 매니페스트에 포함했고 `jar tf`와 `check-shading.sh` 결과를 보고서에 붙였다.

## 3. 영역별 DoD

### 3.1 에이전트

- 컴파일 타겟 Java 8. 모든 클래스 major version 52 확인 테스트가 있다.
- `argos-agent.jar`에 `io.argos.` 와 `io.argos.agent.shaded.` 외의 **클래스**가 없다. `META-INF/LICENSE`, `META-INF/NOTICE`, `META-INF/THIRD-PARTY-NOTICES`, `META-INF/argos-deps.txt`, `META-INF/sbom/`은 반드시 존재한다(`check-shading.sh`가 모두 확인).
- `javap`로 jar 안 모든 클래스의 `sun/misc/Unsafe` 참조를 검사하는 테스트가 있고 허용 목록 밖 참조가 0이다. JDK 25 매트릭스는 `--sun-misc-unsafe-memory-access=deny`로 통과한다.
- 계측 모듈마다 대상 라이브러리 버전 범위를 모듈 README에 명시하고, 각 경계 버전에 통합 테스트가 있다. 모듈 활성 전 witness 검사(대상 클래스·메서드 존재 확인)가 있다.
- 변환 클래스 목록이 승인된 베이스라인과 일치한다. ByteBuddy `onError`·`ClassCircularityError` 0.
- 통합 테스트가 `-XX:+BytecodeVerificationLocal`로 통과한다.
- JDK 17·21·25에서 JDK 클래스 계측(`HttpURLConnection`·`ThreadPoolExecutor`·`CompletableFuture`)이 `IllegalAccessError` 없이 동작한다.
- 1요청 1트랜잭션 테스트: 예외·404·`sendError`·JSP forward·`AsyncContext.dispatch` 각각에서 트랜잭션 정확히 1건, 서비스 이름에 `/error` 없음, 상태 코드가 최종값(D-04, D-21).
- JDBC 중첩 제거 테스트: HikariCP + 각 드라이버에서 SQL 1회 실행 = SQL step 1개, `sql_count` 1(D-24). DBC·COMMIT step 기록.
- 풀·Tomcat 메트릭이 JMX 비활성 상태(Spring Boot 기본)에서 수집된다.
- 가상 스레드 모드(JDK 21+)에서 트랜잭션 수가 플랫폼 스레드 모드와 같고, `cpu_time_ms`·`alloc_bytes`는 결측으로 기록되며(0이 아님), 스레드 덤프에 가상 스레드가 포함되고, 스레드 이름 사전이 1,000을 넘지 않는다.
- 재진입 테스트: 에이전트 자신의 송신·스케줄 스레드가 만든 작업이 step으로 기록되지 않는다.
- Executor 허용목록 밖 클래스는 변환되지 않고(베이스라인 diff), `ThreadPoolExecutor.remove()`·`ScheduledFuture.cancel()` 동작이 보존된다.
- fail-safe 테스트: Advice 내부 예외 주입 시 샘플 앱 요청이 정상 응답하고, transform 오류 임계 초과 시 모듈이 자동 비활성되며, `instrumentation.exclude-classes`가 동작한다.
- 컨텍스트 누수 테스트: 1만 요청 후 ThreadLocal 잔존 0, 활성 트랜잭션 레지스트리 잔존 0, 약참조 맵은 GC 후 잔존 0, 독립 Tomcat WAR 재배포 50회 후 웹앱 클래스로더 잔존 1.
- 오버헤드 벤치 결과가 N-01~N-04·N-26~N-30 이내이고(01 문서 7.3 프로토콜), 결과 파일이 `docs/bench/`에 날짜·커밋과 함께 기록됐다. 에이전트 스레드 ≤ 6, 직접 메모리 ≤ 8MB, 메타스페이스 증가 ≤ 32MB가 72시간 보고서에 있다.
- 정상 시나리오에서 에이전트 로그에 ERROR 0, 허용목록 밖 WARN 0, stdout/stderr 출력 0.
- INFO 레벨 1만 요청 후 로그에서 PII 시드 grep 0건(SEC-26). 토큰 원문 grep 0건(SEC-06).
- Advice 소스에 람다·`skipOn`·`readOnly=false`·`synchronized`·블로킹 호출·리플렉션 조회가 없음을 ArchUnit이 검사한다.
- 환경 덤프 마스킹 grep 0건(SEC-20), 원격 변경 하드 캡 거부 테스트(SEC-23), 금지 접두사(SEC-25).

### 3.2 수집 서버

- OpenAPI 스펙 파일이 갱신됐고 스펙 린트가 통과한다(모든 엔드포인트에 `x-argos-role`). API 변경은 계약 테스트가 있고 OpenAPI 호환 diff가 breaking을 잡는다.
- 통합 테스트는 Testcontainers로 실제 ClickHouse·PostgreSQL을 띄워 적재·조회를 검증한다. Mock으로 대체하지 않는다.
- 빈 DB와 "이전 버전 스키마 + 1/100 데이터" 두 경로에서 마이그레이션이 자동 적용되고 멱등하며, 각 스크립트의 소요 시간이 보고서에 적혀 있다(N-22).
- D-03·D-12·D-13 정합 테스트가 통과한다(중복 재전송·`kill -9` 재시작·ClickHouse 30분 중단 후 복구·늦은 도착 시나리오 포함): "보낸 행 수 = count(xlog) = Σ service_stat_1m.count".
- ClickHouse 쿼리는 전부 읽기 전용 사용자·쿼리 설정 경유. `system.query_log`로 검증하는 테스트가 있다. insert는 명시 컬럼 목록·`async_insert=0`·중복 제거 토큰.
- 수집 경로 변경 시 부하 테스트(1,000 TPS 5분)가 통과하고 적재 지연 p99 5초 이하(`argos_ingest_lag_seconds`)를 기록했다.
- 모든 조회 API에 타임아웃·행 제한·범위 상한·권한 검사가 있고 응답에 `source: raw|1m|1h`가 포함되는 계약 테스트가 있다. 분 경계 미정렬 범위에서 대시보드 적분과 XLog 점 수가 일치한다.
- 입력 검증 실패는 4xx + 표준 에러 본문, 서버 오류는 5xx + 요청 id. 스택·내부 경로·SQL은 응답에 노출되지 않는다.
- 자기 메트릭에 저장소 지표(활성 parts, DelayedInserts, 적재 지연, 디스크 여유, 사전 미해결 수, 늦은 도착·시계 보정 수, 쿼터 드롭)가 포함된다.
- 알림 규칙 변경 시 상태 전이 테스트(지속 시간·복구 임계치·NO_DATA·기동 유예·최소 표본)가 통과한다.

### 3.3 UI

- 화면마다 Playwright E2E가 핵심 시나리오 1개 이상을 커버한다(로그인 → 화면 진입 → 핵심 동작 → 결과 확인).
- 05 문서 2장에 그 화면의 "필수 요소"가 있으면 항목별로 구현 여부를 완료 보고에 표로 적고, 빠진 항목은 사유를 쓴다.
- 모든 화면 상태(앱·환경·시간 범위·필터·선택·종류)가 URL에 반영되고, 그 URL을 새 탭에서 열면 같은 화면이 나온다(F-U14). 비로그인 상태에서 열면 로그인 뒤 원래 URL로 돌아온다.
- 시간 범위는 전역 상태 하나이고, 차트 드래그·XLog 드래그·딥링크가 같은 상태를 바꾼다(05 문서 2.0).
- 로딩·빈 상태·에러 상태가 모두 구현되고("다음 행동" 문구 포함) 스크린샷 테스트가 있다.
- 문자열은 i18n 키로만(en 원본, ko 번역). 하드코딩 문자열을 찾는 린트가 통과한다. 부록 B 용어표를 ko 값에 적용했다.
- 1366×768에서 가로 스크롤이 없다.
- API 호출은 생성된 클라이언트만 사용한다. `fetch` 직접 호출 없음. 토큰은 쿠키로만(SEC-40).
- 수집 데이터를 그리는 코드는 HTML 문자열을 조립하지 않는다(`react/no-danger` 통과). XSS 시드 E2E 전역 훅이 그 화면을 순회한다(SEC-62). CSP 위반 0건.
- 실시간 화면은 WebSocket 끊김·재접속·로그아웃 시 종료 시나리오 테스트가 있다.
- 키보드로 주요 동작(시간 범위 변경·이동·확대, 목록 탐색, 상세 열기, 검색)이 가능하다.
- 표는 정렬·열 필터·값 클릭 필터·CSV(수식 주입 방지)를 공통 컴포넌트로 제공한다.

### 3.4 설치·운영

- 깨끗한 VM에서 설치 가이드만 보고 프로젝트 비참여자가 설치에 성공한다(사람 검증, 소요 시간 기록).
- 데모 프로파일이 60초 안에 XLog 점을 보여준다(N-16).
- 설치 직후 상태: 기본 비밀번호 없음(`.env` 랜덤 생성·0600), 노출 포트 = {8080, 9100}, 설정 토큰 없이 마법사 접근 불가(SEC-47·74·75).
- 업그레이드 스크립트가 지원 중인 모든 이전 마이너 데이터가 있는 상태에서 성공하고 데이터가 보존된다(자동 테스트).
- 서비스 중지·재시작 후 데이터 손실 없음(WAL 복구 테스트).
- 에어갭 테스트에서 외부 egress 0이 패킷 캡처로 자동 검증된다(N-17). 릴리스 자산 검증 스크립트가 통과한다.
- 진단 번들 스크립트가 로그·설정·버전·시스템 정보를 모으고 토큰·비밀값을 마스킹한다.

### 3.5 보안

- 인증·권한 매트릭스 테스트(SEC-49)가 전체 엔드포인트를 커버하며, 역할 표기가 없는 엔드포인트가 있으면 린트가 실패한다.
- 토큰 수명주기 테스트: 발급(원문 1회), 해시 보관, 회전 중 동시 유효, 폐기 즉시 세션 종료, 만료 거부(SEC-01~06).
- 수집 경로 상한 테스트 5종(SEC-11~15)과 서버 메모리 상한 유지.
- 원격 변경 하드 캡·환경 덤프 마스킹·금지 접두사·명령 TTL 테스트(SEC-20~25).
- PII 시드 테스트(N-10c): 기본 설정에서 ClickHouse·PostgreSQL 전체 grep 0건. 삭제 API 후 0건.
- XSS 시드 E2E(SEC-62)와 CSP 위반 0건. CSV 수식 주입 방지.
- SSRF 테스트: 금지 대역 웹훅 저장·테스트 전송 거부, 리다이렉트 미추종(SEC-51). 채널 비밀값 DB 평문 부재(SEC-52).
- 세션 테스트: 쿠키 플래그, 리프레시 회전·재사용 탐지, 로그아웃·역할 변경 즉시 무효화, CSRF, WS Origin(SEC-40~44).
- 보안 헤더·CSP 단언 통합 테스트(SEC-45·46).
- SBOM 생성·동봉·스캔이 CI에서 돌고 Critical·High 0 또는 승인된 예외 문서(SEC-70·71).
- 비밀 스캔(gitleaks) 0건, 저장소에 자격증명 리터럴 없음(SEC-73·74).
- 감사 이벤트 카탈로그 스냅샷 테스트(SEC-80).
- 보안 테스트 스위트 `./gradlew securityTest`가 CI에서 분리 실행된다(SEC-93).

## 4. 단계 게이트

### Gate 0: PoC 완료

## 5. 사람의 수락 테스트 절차

WO가 REVIEW 상태가 되면 사람이 수행한다. 15분 이내로 설계한다.

1. 완료 보고서를 읽고 공통 DoD 체크리스트에 빈 항목이 없는지 확인한다. 빈 항목이 있으면 즉시 반려.
2. CI 결과(링크)가 녹색인지 확인한다. 핵심 경로 변경이면 nightly 매트릭스·벤치 결과도 확인한다.
3. WO의 "수락 시나리오"를 그대로 수행한다. 보통 샘플 앱 기동 → 요청 → 화면 또는 로그 확인.
4. 결과를 WO의 상태 표에 기록한다: `DONE(날짜)` 또는 `REJECTED(날짜, 사유)`.
5. 반려 시 사유를 WO에 추가하고 같은 WO를 다시 지시한다. 사유는 재현 가능하게 쓴다.

**핵심 경로는 사람이 코드도 읽는다**: 에이전트 코어·전송·클래스로더·Advice, 서버 수집 파이프라인(WAL·중복 제거), 토큰 검증·세션 관리, 원격 명령 처리(에이전트·서버 양쪽), 마스킹·정규화 코드, 웹훅 전송, 마이그레이션. 전부가 아니라 설계 의도와 맞는지, 예외가 삼켜지고 있지 않은지, 상한이 있는지를 본다.
