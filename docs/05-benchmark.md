## 0. 목적

"상용 SW 수준"을 추상적으로 두지 않고 **참조 제품이 실제로 하는 것**으로 정의한다. 제품 기능의 참조는 셋, 프로젝트 운영의 참조는 넷이다.

| 참조 제품 | 역할 | 기준으로 삼는 이유 |
|---|---|---|
| **Datadog APM** | 트레이스 분석·에러 추적·알림·서비스 맵의 상한선 | 글로벌 SaaS 중 기능 완성도가 가장 높다. 트레이스 상세, 에러 그룹화, 배포 추적, 알림 상태 머신, Remote Configuration의 기준 |
| **Jennifer** | 국내 운영 현장의 실시간 모니터링 표준 | X-View(산점도), 액티브 서비스, 1초 실시간, 자동 스택트레이스, SQL 통계, 커넥션 대기 표시처럼 국내 운영자가 "당연히 있어야 한다"고 여기는 화면의 기준 |
| **Prometheus + Grafana + Alertmanager** | 메트릭·대시보드·알림 라우팅의 사실상 표준 | 메트릭 명명, 알림 규칙(`for`), 라우팅·그룹핑·억제·음소거, 대시보드 변수·주석, 셀프 메트릭 노출의 기준. 운영 현장 대부분이 이미 쓰고 있어 상호운용이 중요 |
| **Prometheus · Grafana · OpenTelemetry · SigNoz** (프로젝트 운영) | 릴리스·보안·호환성 약속·빠른 시작의 기준 | 1.9장 |

보조 참조: Scouter(XLog 데이터 모델, 제외 패턴), Pinpoint(분산 추적·호출 트리), OpenTelemetry Java Agent(계측 구조, Apache-2.0이라 코드 참고 가능).

각 기능의 **Argos 1.0 목표**는 네 단계로 적는다.

| 표기 | 의미 |
|---|---|
| **동등** | 참조 제품과 같은 수준으로 1.0에 포함. 03 문서 Gate 2 조건 |
| **부분** | 핵심만 1.0에 포함, 나머지는 1.x. 범위를 비고에 명시 |
| **1.x / 2.0** | 1.0에서 제외, 이후 버전 |
| **비범위** | 의도적으로 따라가지 않음. 이유를 6장에 적는다 |

## 2. 화면별 필수 요소 (UX 벤치마크)

03 문서의 UI 수락 기준에 그대로 쓴다. "참조"는 그 화면이 따라야 할 기준 제품이다. Claude Code는 UI WO 완료 보고에 해당 절의 항목별 구현 여부를 표로 적는다.

### 2.0 모든 화면 공통 (참조: Grafana 시간 범위 모델 + Datadog 패싯)

- 시간 범위는 전역 상태 하나다. 상단 선택기, 시계열 차트 드래그 확대, XLog 드래그, 알림 딥링크가 모두 같은 상태를 바꾸고, 앱 전환·화면 전환 시 유지된다.
- 실시간 모드 중 과거를 드래그하면 실시간이 해제되고 "실시간 재개" 버튼이 보인다. 재개 시 공백을 REST로 보충한다.
- 시간 범위 이동(이전·다음), 확대(1/2), 축소(2배), "지금으로"에 단축키가 있다. 프리셋은 5m·15m·1h·6h·24h·7d·30d와 오늘·어제.
- 모든 표: 셀 값 클릭(또는 우클릭 메뉴) → "이 값으로 필터" / "이 값 제외". 적용된 필터는 상단 칩으로 표시하고 개별 제거할 수 있다. 필터는 URL에 포함된다.
- 모든 시계열 차트: 점 클릭 → 그 시각 ±(범위의 1/60, 최소 1분)의 XLog 또는 관련 목록으로 가는 메뉴. 이벤트 마커(배포·기동·종료·설정 변경·알림 전이)와 수집 중단 음영(D-18)을 표시한다.
- 트랜잭션 종류(요청/배치/메시지) 필터는 전역이며 기본 "요청"이다(D-20). 환경 필터도 전역이다.
- 딥링크 수락 기준(알림·공유 링크 공통)
  1. 비로그인 상태에서 열면 로그인 뒤 원래 URL로 돌아온다.
  2. 알림에서 온 링크는 발화 시각 기준 고정 범위(기본 ±15분)이고 실시간 모드가 아니다.
  3. 알림 대상(앱·환경·인스턴스·서비스·호스트) 필터가 적용되어 있다.
  4. 해당 알림 이벤트와 상태 전이가 차트에 마커로 보인다.
  5. 보존 기간 안에서는 1주 뒤에 열어도 같은 데이터가 보인다.
- 로딩·빈 상태·에러 상태 문구는 "다음 행동"을 포함한다(예: "선택 기간에 트랜잭션이 없습니다. 기간을 넓히거나 필터·종류를 확인하세요"). 제외된 요청이 있으면 "제외 N건" 링크를 함께 보여준다.
- 타임스탬프는 브라우저 시간대로 표시하고, 알림 메시지는 서버 설정 시간대와 UTC 오프셋을 함께 적는다.
- 수집 데이터(서비스 이름·URL·SQL·예외·헤더·user_id 등)는 모두 텍스트 노드로만 렌더한다(SEC-60).

### 2.1 XLog (참조: Jennifer X-View)

- x축 시간, y축 응답시간(선형·로그 전환), 점 색 3종(정상·지연·에러), 지연 임계선 표시.
- 드래그 사각형 → 선택 영역 요약 패널(선택 점 수, 서비스별 상위 10(건수·평균·최대·에러), 인스턴스별·에러 클래스별·HTTP 상태별 분포, 요약 행 클릭 → 목록 필터) + 트랜잭션 목록.
- 색 기준 전환: 상태(기본) / 인스턴스 / 서비스 상위 N.
- 실시간 모드: 좌로 흐르는 5분 창, 일시정지, 재개 시 공백 보충.
- 점 호버: 서비스명, 응답시간, 상태, 인스턴스. 클릭: 상세.
- 서비스·인스턴스·에러·종류 필터가 산점도에 즉시 반영. 종류=배치면 y축 단위를 초·분으로 자동 전환.
- 10만 점 초과 시 서버 샘플링 표시("표시 N / 전체 M"). 샘플링은 결정적이어서 새로고침해도 같은 점이 보인다.
- 트랜잭션 목록 필수 열: 시각, 서비스, 응답시간, HTTP 상태, 에러 클래스, 인스턴스, SQL 수·시간, 외부 호출 수·시간, 사용자 ID(수집 시), 프로파일 유무, 종류, 버전. 열 선택·정렬·CSV.
- 목록에서 위·아래 키 이동, Enter로 상세, 상세에서 이전·다음 트랜잭션 이동.
- 수집 중단 구간 음영, 이벤트 마커.

### 2.2 트랜잭션 상세 (참조: Datadog 트레이스 뷰 + Jennifer 프로파일)

- 상단 요약: 서비스, 응답시간, 상태, 시각, 인스턴스, 환경, 버전, 종류, 스레드, CPU 시간·할당 메모리(가상 스레드면 "측정 불가"), SQL 수·시간, 커넥션 대기 합계, 외부 호출 수·시간, 에러 여부, trace id, 사용자 ID, 원격 IP(마스킹 표시), 수집된 헤더·요청 ID, 호출자 앱·서비스·인스턴스.
- "같은 서비스·같은 기간의 p50·p95와 이 요청의 백분위 위치"를 표시하고, "정상 요청 1건 나란히 보기" 버튼으로 두 타임라인을 좌우로 놓는다.
- 타임라인(워터폴): step을 시간축 막대로, 부모·자식 들여쓰기, 비율. "계측되지 않은 시간(self time)" 구간을 회색으로 표시하고 step 합계와 응답시간 차이가 20% 이상이면 강조. 자동 스택 캡처가 있으면 그 구간에 스택 아이콘.
- 호출 트리 탭: step 트리, 연속 반복 step 접기(횟수·합계). 배치 트랜잭션은 청크 반복을 접힌 요약으로.
- SQL 탭: 정규화 SQL과 원문, 바인드 파라미터(모드·권한에 따라), 실행시간·fetch 시간·행수, 커넥션 대기 합계와 실행 합계 분리(대기 step에 풀 이름), 같은 SQL 통계로 이동.
- 외부 호출 탭: 호스트·경로·시간·상태(TIMEOUT / CONNECT_FAIL / 5xx 구분), 호스트 통계로 이동, 분산 트레이스로 이동.
- 에러 탭: 예외 클래스·마스킹된 메시지·스택(앱 프레임 강조), 에러 그룹으로 이동.
- STACK step 뷰: 연속 캡처된 스택을 나란히 두고 공통 프레임을 강조.
- 프로파일 미수집 시 사유(샘플링 / 유실) 표시(D-07).
- 호출자(상위) 트랜잭션으로 이동. "로그 열기"(F-U18). 트랜잭션 JSON 내보내기. URL 복사.

### 2.3 대시보드 (참조: Jennifer 실시간 대시보드 + Grafana 패널 상호작용)

### 2.4 알림 규칙 편집 (참조: Datadog Monitor + Alertmanager)

- 필드: 대상(앱·환경·인스턴스·서비스·외부 호스트), 종류(요청/배치), 지표, 평가 창(window), 지속 시간(for), 평가 단위(앱 전체/인스턴스별), 조건(연산자, 경고·심각 임계치), 최소 표본 수, no-data 처리, 복구 임계치·복구 지속, 기동 유예, 활성 시간대, 반복 음소거 일정, 심각도별 채널, 재알림 간격, `runbook_url`, 메시지 템플릿(허용 변수만).
- 미리보기: 최근 7일 데이터로 발화 시각·횟수·최대 지속을 차트에 표시(야간 임계 튜닝용).
- "템플릿에서 만들기": 기본 템플릿 목록(01 문서 부록 A) → 값 조정 → 저장. 템플릿과 달라진 필드 표시.
- 규칙 복제(다른 앱·환경으로), 규칙 비활성(삭제와 구분), 변경 이력.
- 채널 설정: 목적지 검증 결과 표시, 비밀값 마스킹, 테스트 전송 버튼(같은 검증).

### 2.5 서비스·SQL·외부 호출·에러 통계 (참조: Datadog 서비스 페이지)

- 모든 표: Top N, 정렬 기준 전환(총 시간·횟수·평균·p95·에러), 값 클릭 필터, 직전 동일 기간 대비 변화율 열(건수·p95·에러율), 종류·환경 필터, 열 필터, CSV.
- 서비스 상세: 추이 차트(선택 기간), 버전별 분리, 인스턴스별 분포, 그 서비스의 SQL Top N·외부 호출 Top N·에러 그룹 Top N(교차 뷰), 관련 트랜잭션(XLog 필터 적용 상태로 이동).
- SQL 상세: 추이, 이 SQL을 실행하는 서비스 목록(건수·비중), 실행 인스턴스 분포, DB(데이터소스)별 분리, 커넥션 대기 합계, 정규화 SQL·원문, 관련 트랜잭션("프로파일 수집 트랜잭션만 표시" 명시).
- 외부 호출 통계: 호스트(+경로 패턴)별 호출수·p50/p95·에러 수·타임아웃 수·연결 실패 수, 추이, 호출 서비스, 관련 트랜잭션, 애플리케이션 맵의 외부 노드와 연결.
- 에러 분석: 그룹(지문)별 횟수·최초·최근 발생, "신규(최초 발생이 선택 기간 내)" 필터, 대표 스택(앱 패키지 프레임 강조, 설정 `app-packages`), 마스킹된 메시지 패턴, 영향 서비스, 버전별·인스턴스별 분포, 같은 그룹의 최근 트랜잭션 10건.

### 2.6 액티브 트랜잭션 (참조: Jennifer 액티브 서비스)

- 인스턴스별 막대(진행 중 수), 경과 시간 구간별 색 4단계(기본 1초 미만 / 1~3초 / 3~8초 / 8초 이상, 설정 가능). 막대 클릭 → 그 인스턴스로 필터.
- 목록 필수 열: 인스턴스, 서비스, 경과 시간, 현재 상태(SQL 실행 중 + SQL 요약 / 외부 호출 중 + 호스트 / 커넥션 대기 + 풀 / 메서드 실행 중), 스레드 이름, 사용자 ID·IP(수집 시), 종류, 시작 시각.
- 기본 정렬 경과 시간 내림차순, 5초 갱신("N초 전 기준" 표시), 일시정지, 인스턴스·서비스·종류·상태 필터.
- 행 선택 → "이 스레드 스택 보기"(단일 스레드 스택 명령) / "이 인스턴스 스레드 덤프" / "같은 서비스의 최근 완료 트랜잭션".
- 상단 요약: 전체 진행 중 수, 8초 이상 건수, 인스턴스별 최대. 액티브 수 알림 규칙으로 가는 링크.
- WebSocket 끊김 시 "갱신 중단 N초" 배지, 재접속 시 자동 복구.

### 2.7 인스턴스 상세·스레드 덤프 뷰어 (참조: Jennifer 인스턴스/스레드, Datadog Host)

- 상단: 상태(F-S28), 앱·환경·버전·에이전트 버전(구버전·호환 불가 경고)·JVM·OS·호스트·PID·cgroup 여부·기동 시각·업타임·선택 기간 재기동 횟수, 시계 차이, 드롭, 모듈 자동 비활성 여부, IP 수집 모드, 가상 스레드 모드.
- 차트: 힙 영역별 사용·최대, GC 횟수·정지 시간(수집기별), 스레드(live/daemon/peak), 클래스 로딩, CPU(프로세스·시스템, 컨테이너 한도 기준), FD, Tomcat 커넥터별 스레드·연결, 커넥션 풀별 active/idle/waiting/max, 시스템(CPU·메모리·디스크·네트워크). 커서 동기화·이벤트 마커·비교 기준선.
- 환경 탭: JVM 옵션, 시스템 프로퍼티·환경변수(마스킹 적용 상태로, 관리자만), 에이전트 유효 설정과 각 항목의 출처(파일/환경변수/서버 푸시), 원격 변경 허용 키 목록, 계측 모듈 상태(활성/자동 비활성·에러 카운트), 최근 자가 진단 결과(오버헤드·드롭·캡처 비용).
- 명령 탭: 요청·결과 이력(요청자·시각·소요·결과 크기), 스레드 덤프·단일 스레드 스택·자가 진단(운영자) / 설정 리로드·환경 덤프(관리자) 실행 버튼, 감사 기록.
- 스레드 덤프 뷰어: 상태별 그룹·건수(RUNNABLE/BLOCKED/WAITING/TIMED_WAITING), 동일 스택 묶기(풀 유휴 스레드 접기), 락 보유·대기 관계와 데드락 표시, 가상 스레드 구분, 스레드 이름·클래스·메서드 검색, 진행 중 트랜잭션과 매칭(스레드 → 트랜잭션 링크), 원문 다운로드(.txt), 최근 20개 보관, 잘림 표시(스레드당 깊이 상한 64, 초과 시 전체 파일 다운로드). 두 덤프 비교는 1.x.
- 링크: 이 인스턴스의 XLog·액티브 트랜잭션·알림 이력·설정 변경 이력.

### 2.8 트레이스 뷰 (참조: Datadog 트레이스 뷰, Pinpoint 호출 트리)

- 트리 + 타임라인. 노드마다 앱(환경)·서비스·인스턴스·시간·상태·에러·버전.
- D-05에 따라 호출자 HTTP step과 피호출자 트랜잭션을 둘 다 그리고, 차이를 "네트워크·대기"로 표시한다.
- 누락 노드 구분: 피호출자가 미계측(에이전트 없음)이면 외부 호출 노드로, 수집 지연·유실이면 "아직 수집되지 않음(다시 조회)"로, 프로파일 미수집이면 D-07 사유로.
- 임계 경로(critical path) 강조, 노드 클릭 → 트랜잭션 상세, 앱 노드 → 그 앱 대시보드(같은 시간 범위).
- trace id 복사, 로그 열기(F-U18), 트레이스 JSON 내보내기.

### 2.9 알림 이력 (참조: Alertmanager UI + Datadog Monitor Status)

- 상단 고정: 현재 발생·확인 목록(전 앱 또는 선택 앱), 심각도별 건수, 채널 상태(채널별 최근 전송 성공·실패 시각).
- 목록 필수 열: 시각, 앱(환경), 대상(인스턴스·서비스·호스트), 규칙, 심각도, 상태 전이(대기→발생→확인→해제, 데이터 없음), 현재값·임계치, 지속 시간, 전송 결과(채널별 성공·실패·재시도 수), ACK 사용자.
- 필터: 기간·앱·환경·심각도·상태·규칙·"전송 실패만".
- 행 동작: 딥링크(2.0 기준), 규칙 편집, ACK(메모), "이 대상 알림 일시 중지(점검)" 바로 만들기.
- 알림 통계(최근 7일·30일): 규칙별 발화 수·평균 지속·ACK까지 시간·해제까지 시간. 노이즈 규칙을 찾는 용도.
- 전 앱 보기는 전체 현황에서 진입한다(app_id 필수 예외).

### 2.10 전체 현황 (참조: Datadog 서비스 목록 + Jennifer 멀티 도메인 대시보드)

- 로그인 후 기본 화면. 환경·앱 그룹 필터, 카드/표 전환, 상황판 모드(F-U21).
- 앱 행·카드 필수 항목: 상태(가장 나쁜 인스턴스 기준), 인스턴스 UP/전체, TPS, p95, 에러율, 액티브, 진행 중 배치 수, 발화 중 알림(심각도별), 최근 배포 시각·버전, 1시간 스파크라인(TPS·p95·에러율).

- 전 앱 발생 중 알림 요약 패널, 수집 서버 자기 상태(적재 지연·디스크·채널 실패·세션 수·인증서 만료).
