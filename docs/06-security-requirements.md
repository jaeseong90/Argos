## 0. 읽는 법

각 요구는 **요구 / 기본값·수치 / 검증 방법 / 단계**를 가진다. "자동"은 CI 테스트, "수동"은 03 문서 5장 절차. 단계는 **M** = Gate 1(MVP) 전, **G2** = Gate 2 전, **1.x** = 이후. 기본값은 "설정 없이 안전"이어야 하며, 안전을 끄는 설정은 명시 플래그와 경고가 함께 있어야 한다.

신뢰 경계는 넷이다. (a) 계측 대상 앱 JVM 안의 에이전트, (b) 에이전트↔서버 gRPC, (c) 서버↔브라우저·알림 채널, (d) 서버↔ClickHouse·PostgreSQL·백업. 공격자 모델은 "앱 서버 로컬 계정 탈취자", "같은 망의 중간자", "조회자 권한의 내부자", "운영자 계정 탈취자", "서버 호스트 침해자", "공급망 오염자"다. 위협 모델 전문은 `docs/security/threat-model.md`(SEC-91)에 둔다.

## 2. 요구사항

### A. 에이전트 토큰과 세션

| ID | 요구 | 기본값·수치 | 검증 | 단계 |
|---|---|---|---|---|
| SEC-01 | 에이전트 토큰은 **앱 단위**로만 발급한다. 전역 토큰 개념을 제거한다. 토큰은 서버에서 32바이트 CSPRNG로 생성하고 `argos_` 접두사 + base64url로 표시한다 | 토큰 1개 = 앱 1개. 앱당 활성 토큰 최대 5개 | 자동: 다른 앱 이름으로 Hello 시 `PERMISSION_DENIED`. 접두사·길이 단위 테스트 | M |
| SEC-02 | 서버는 토큰 원문을 저장하지 않는다. `agent_tokens`에는 SHA-256 해시, 앞 8자(식별용), 발급자, 발급·만료·마지막 사용 시각, 상태만 둔다. 원문은 발급 응답에 1회만 포함한다 | | 자동: 발급 후 DB에 원문 부재, 재조회 API에 원문 없음. 정적: 토큰 로그 출력 금지 린트 | M |
| SEC-03 | 토큰에 만료일을 둘 수 있고(기본 무기한, 권장 1년), 만료 30일 전부터 관리 화면 경고와 알림 규칙(`agent_token_expiring`)을 제공한다 | UI 발급 폼 기본 365일 | 자동: 만료 토큰 접속 거부, 경고 메트릭 | G2 |
| SEC-04 | **회전**: 새 토큰 발급 후 구 토큰에 유예 기간을 두어 두 토큰이 동시에 유효하다. **폐기**: 폐기 즉시 그 토큰의 모든 세션을 `UNAUTHENTICATED`로 종료하고 재접속을 거부한다 | 유예 기본 7일 | 자동: 폐기 → 활성 세션 5초 내 종료 → 재접속 거부. 회전 중 두 토큰 동시 접속 성공 | M |
| SEC-05 | 토큰별 **접속 상한·레이트 리밋**: 동시 세션 수, 분당 신규 세션 수, 미인증 Hello 실패 수(IP 기준) 제한. 초과 시 `RESOURCE_EXHAUSTED` + 메트릭 + 감사 로그 | 토큰당 동시 세션 100, 분당 신규 60, IP당 인증 실패 분당 20 → 10분 차단 | 자동: 가짜 에이전트로 한도 초과 재현 | G2 |
| SEC-06 | 에이전트 토큰 보관: `server.token`, `server.token-file`(0600 권장), `ARGOS_TOKEN` 세 방식. yml 평문이면 기동 시 WARN 1회. 에이전트 로그·자가 진단·진단 번들·설정 해시 입력에서 토큰은 항상 `argos_****`로 마스킹 | | 자동: 평문 설정 WARN 단언, 번들 출력 grep 0건 | M |

### B. 전송 보안

|---|---|---|---|---|

| SEC-10 | mTLS(에이전트 클라이언트 인증서)는 1.x 옵션으로 설계에 자리를 둔다. 1.0은 토큰 + 서버 TLS. 자체 CA 운영 가이드(CA 키 보관, 발급·갱신, 폐쇄망 배포) 포함 | | 수동: 가이드만 보고 비참여자가 자체 CA로 설치 | 1.x(설계)·G2(가이드) |
