## Method

- Stack: PostgreSQL and ClickHouse (Testcontainers), the server boot jar as a child JVM, toxiproxy (pinned by digest) between the agent and the collector, shop-boot3 with the agent on JDK 21, ext-stub in process. 18 §11.1 describes a Compose stack and `docker stop argos-server`; the runner stops the server JVM (SIGTERM on POSIX) and starts it again on the same WAL.
- Load: the demo load generator (`sample-apps/load`, open model, fixed rate) instead of k6 (18 §11.1); one run per scenario over baseline, fault and recovery, a p99 per 10 s interval.
- Noise band: upper = max(baseline interval p99) + max(spread, 10 % of the baseline median); the first baseline interval is left out; the fault window is judged by the median of its interval p99 values.
- Recovery: from the fault's removal until the instance is UP or WARN with a heartbeat after the removal and the first xlog row of a transaction after the removal is stored; target 60 s.
- Drop accounting: stored xlog rows + agent drops (`argos_agent_dropped_total{queue="transaction"}`) + server drops seen by the agent = answered requests (a range when requests had no answer).
- Verdicts: invariants are PASS/FAIL in every run; timing and p99 rows only in a valid run; INFO rows are references.
