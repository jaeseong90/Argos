# Argos APM web UI

React + TypeScript (strict) + Vite, managed with pnpm. Design: [docs/15-ui-design.md](../docs/15-ui-design.md); build rules: [docs/19-repo-build-release-design.md](../docs/19-repo-build-release-design.md) §4–§5.

## Requirements

- Node.js 24 LTS (`.nvmrc`; `package.json#engines` requires `>=24.14.0 <25`, enforced by `engineStrict`)
- pnpm through Corepack (bundled with Node.js 24). The exact pnpm version is pinned in `package.json#packageManager` and in `pnpm-lock.yaml`.

```sh
corepack pnpm install --frozen-lockfile
```

From the repository root:

- with a standalone pnpm on `PATH` (for example installed by `pnpm/action-setup`), `pnpm -C ui build` works; pnpm switches itself to the pinned version;
- Corepack picks the pnpm version from the `package.json` of the _current_ directory (the root has none), so either run it inside `ui/` or name the version: `corepack pnpm@12.14.0 -C ui build`.

## Scripts

| Script               | What it does                                                                                                                                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `build`              | `tsc -b`, `vite build`, license check of the bundled packages (writes `dist/licenses.txt`), external-resource check                                                                                              |
| `test`               | Vitest: UI tests (jsdom) and tooling tests (node: scripts, ESLint rules, helpers of the Playwright suites)                                                                                                       |
| `lint`               | ESLint, zero warnings allowed                                                                                                                                                                                    |
| `typecheck`          | `tsc -b` over the app, Vite config, tooling scripts (`checkJs`) and the Playwright suites (`e2e/`, `perf/`)                                                                                                      |
| `format:check`       | Prettier check (`format` rewrites files)                                                                                                                                                                         |
| `check:i18n`         | `scripts/check-i18n-keys.mjs`: keys used in code missing from `en`, orphan `ko` keys/namespaces (errors); untranslated keys, missing language directories or namespace files (warnings, errors with `--release`) |
| `check:external`     | `scripts/check-no-external.mjs`: no reference to another origin in `dist/` or `index.html` (needs a build)                                                                                                       |
| `check:licenses`     | `scripts/check-licenses.mjs`: license allowlist for the production dependency closure, and for the bundled packages when `dist/` exists                                                                          |
| `dev` / `preview`    | Vite dev server / preview of `dist/`                                                                                                                                                                             |
| `e2e`                | `vite build`, then the Playwright E2E suite (`e2e/specs`, Chromium) against `vite preview` of `dist/`. Not part of `test`                                                                                        |
| `perf`               | `vite build`, then the XLog frame-time spec (`perf/xlog-frame.spec.ts`, T-NFR-14) with Chrome tracing. Not part of `test`                                                                                        |
| `playwright:install` | `playwright install chromium`: downloads the Chromium build the pinned Playwright version uses                                                                                                                   |

The version shown in the UI is `package.json#version`. The build reads no environment variable, and asset hashes use a pinned `hashCharacters`, so the same commit always produces the same `dist/` (docs/16 §10.4). A release changes the version in `package.json` in the release commit.

## Rules enforced by the tooling

- `src/` holds only `.ts`/`.tsx` sources (including `.d.ts`) and static assets (CSS, JSON, images, fonts): `scripts/src-extensions.test.mjs` fails on `.js`, `.jsx`, `.mjs`, `.cjs`, `.mts`, `.cts` or any other file type. The ESLint rules below cover all of these extensions under `src/` as well.
- Every TS/JS file starts with `// SPDX-License-Identifier: Apache-2.0` (`argos/spdx-header`).
- User-facing text comes from `src/locales/<lang>/<namespace>.json` through i18next; English is the source, Korean the translation. Literal strings in JSX text and user-visible attributes fail `i18next/no-literal-string`. Keys are type-checked by `tsc`.
- Translation keys follow docs/15 §12: `<ns>:<area>.<element>`. A key without a prefix is looked up in `common` only, so keys of every other namespace are written with their prefix: `useTranslation(['common', 'xlog'])` and `t('xlog:summary.title')`, not `useTranslation('xlog')` and `t('summary.title')`. Pass the namespaces as an array: i18next's types accept a `<ns>:` prefix only then. `check:i18n` fails an unprefixed key that is not in `common` and says which prefix to use.
- `check:i18n` expects the catalogs of the languages in `src/i18n/resources.ts` (`--languages`, default `en,ko`; a test keeps the two in sync). A missing language directory or namespace file is a warning, and an error with `--release`.
- Untrusted strings reach the DOM only as React text nodes (SEC-60): `react/no-danger` on DOM elements and components, and `no-restricted-syntax` for `dangerouslySetInnerHTML` in any form (JSX attribute, spread or `createElement` props object, member access), `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `createContextualFragment`, `setHTML`/`setHTMLUnsafe`/`parseHTMLUnsafe`, `DOMParser`/`parseFromString`, `document.write`, `eval`, `Function`, `srcdoc` (JSX attribute or property) and `setAttribute` of `srcdoc` or `on*` event handler attributes.
- `fetch`/`XMLHttpRequest` only in `src/api`, `WebSocket` only in `src/realtime`, Ant Design only in `src/components` and `src/app`, uPlot only in `src/charts`, the generated API client only in `src/api`. This covers static imports (`no-restricted-imports`) and `import()` with a literal module name (`no-restricted-syntax`).
- Production code imports only packages listed in `dependencies`.
- Inline `eslint-disable` comments are ignored in `src/`. Exceptions are listed per file, with a reason, in `eslint-allow.json`.
- Bundled packages must be licensed under Apache-2.0, MIT, MIT-0, BSD-2-Clause, BSD-3-Clause, ISC, 0BSD, PostgreSQL, Unicode-DFS or CC0-1.0 (`scripts/license-policy.json`).
- The bundle never references another origin: no external `src`/`href`/`url()`/`@import`, and no absolute URL in any script, stylesheet or markup, also not escaped (`https:\/\/…`) or as a protocol-relative string (`"//host/…"`). Exact URL strings that are never fetched (XML namespaces, links in library error messages) are listed with a reason in `scripts/external-allowlist.json`; escaped URLs are matched in their unescaped form.

## XLog canvas proof of concept (`/xlog-poc`, WO-04)

`corepack pnpm dev` (or `build` + `preview`) and open `/xlog-poc`. The page generates synthetic transactions in the browser (no server): 100,000 points with log-normal response times, Zipf-distributed services, skewed instances, an incident window, and XSS payloads in some service, instance and error class names (they must always render as text). The canvas lives in `src/xlog/` (`XLogBuffer`, `renderer`, `hitIndex`, `selectionSummary`, `engine`, `XLogCanvas`); the demo page in `src/features/xlog-poc/`.

URL parameters (invalid values fall back to the default):

| Parameter     | Values (default)                              | Meaning                                                                                                                                                   |
| ------------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `n`           | 0–150000 (100000)                             | points shown                                                                                                                                              |
| `total`       | > `n`, ≤ 500000 (none)                        | points before the deterministic sample; shows "Showing N of M"                                                                                            |
| `live`        | `0`/`1` (0)                                   | realtime simulation: `rate` points/s in 100 ms batches, 5-minute window                                                                                   |
| `rate`        | 0–5000 (500)                                  | realtime points per second                                                                                                                                |
| `color`       | `status`/`instance`/`service` (status)        | point colour basis                                                                                                                                        |
| `y`           | `linear`/`log` (linear)                       | y axis                                                                                                                                                    |
| `render`      | `pixels`/`path`/`rect` (pixels)               | point drawing: `ImageData` (default, ADR-0003 C-34), one path + fill per colour (docs/15 §7.2 original, comparison), or `fillRect` per point (comparison) |
| `incremental` | `0`/`1` (1)                                   | realtime: shift the point layer and draw only new points                                                                                                  |
| `canvas`      | `gpu`/`cpu` (gpu)                             | `cpu` creates the point layer with `willReadFrequently` (CPU-backed canvas)                                                                               |
| `pointcap`    | 1–3, up to 2 decimals (`POINT_LAYER_MAX_DPR`) | cap of the point layer's backing store scale on high-DPR screens (C-34 measurement option)                                                                |
| `threshold`   | 1–600000 (1000)                               | latency threshold line, ms                                                                                                                                |
| `seed`        | integer (42)                                  | data seed                                                                                                                                                 |
| `perf`        | `0`/`1` (0)                                   | one `performance.measure('xlog:frame')` entry per frame                                                                                                   |

Test hooks:

- `data-testid`: `xlog-poc-page` (with `data-ready="true"` after the first full frame and `data-point-count`), `xlog-canvas`, `xlog-canvas-points` (the plot area: drag inside its bounding box), `xlog-canvas-overlay` (receives pointer events), `xlog-tooltip`, `xlog-tooltip-service`, `xlog-tooltip-elapsed`, `xlog-tooltip-status`, `xlog-tooltip-instance`, `xlog-tooltip-error-class`, `xlog-legend`, `xlog-sampling-indicator`, `xlog-colorby-select`, `xlog-yscale-linear`, `xlog-yscale-log`, `xlog-live-toggle`, `xlog-pause-button`, `xlog-resume-button`, `xlog-threshold`, `xlog-stat-points`, `xlog-stat-visible`, `xlog-stat-frame`, `xlog-stat-dropped`, `xlog-generating`, `xlog-summary`, `xlog-summary-empty`, `xlog-summary-count`, `xlog-summary-sampled`, `xlog-summary-clear`, `xlog-summary-services` (rows `xlog-summary-service-row`), `xlog-summary-instances` (rows `xlog-summary-instance-row`), `xlog-summary-status`, `xlog-summary-http`, `xlog-summary-errors` (rows `xlog-summary-error-row`), `xlog-list`, `xlog-list-count`, `xlog-list-table`, `xlog-list-row`, `xlog-list-filter`, `xlog-list-clear-filter`, `xlog-list-empty`.
- `window.__xlogPerf` (`src/xlog/perf.ts`, `version: 1`): `ready`, `pointCount()`, `visibleCount()`, `samples()` (last 600 frames: `pointsMs`, `overlayMs`, `totalMs`, `interval`, `full`, `drawn`, `passes`, `mode`), `stats()` (count, mean, p50, p95, max), `reset()`, `benchmark({ frames, flush })` (consecutive full redraws; `flush: true` reads one pixel back after each frame so GPU work is included), `lastSelection()` (`points`, `queryMs` (hit index check + rectangle query, docs/15 §7.3; null for a click), `computeMs`, `commitMs` of the last drag). The frame times are main-thread JavaScript times; the `interval` of benchmark frames and Chrome tracing show the real frame rate.

## End-to-end and performance tests (Playwright)

Playwright (`@playwright/test`, Apache-2.0, a devDependency) drives Chromium; the suites are separate from `test` because they need a browser and a build. Install the browser once per machine (it goes to the Playwright cache, `%LOCALAPPDATA%\ms-playwright` on Windows, `~/.cache/ms-playwright` on Linux):

```sh
corepack pnpm playwright:install      # = playwright install chromium (Linux CI: add --with-deps)
corepack pnpm e2e                     # vite build + E2E suite
corepack pnpm perf                    # vite build + XLog frame-time spec (about 12–16 minutes)
```

Both suites serve `dist/` with `vite preview` on `127.0.0.1:4319` (`ARGOS_UI_PORT` changes the port). The preview sends the Content-Security-Policy of docs/16 §9.9 (SEC-46) without its nonce and report parts (`preview.headers` in `vite.config.ts`; the dev server sends none). `ARGOS_UI_BASE_URL=http://host:port` runs them against a server that is already running instead (for example `corepack pnpm dev`), without starting one. Viewport 1366×768, locale `en-US`, Chromium in new headless mode (`channel: 'chromium'`). The E2E suite runs at devicePixelRatio 1; the performance spec runs every scenario at each ratio of `XLOG_PERF_DPR` (default 1 and 2).

The `e2e` and `perf` scripts build first; the suites themselves serve `dist/` as it is. When you run `corepack pnpm exec playwright test` directly, run `corepack pnpm build` first: the global setups (`e2e/fixtures/globalSetup.ts`, `perf/lib/globalSetup.ts`) fail when `dist/index.html` is missing or older than the newest file of `src/`, `index.html`, `vite.config.ts` or `package.json` (not checked with `ARGOS_UI_BASE_URL`).

- **E2E** (`playwright.config.ts`, `e2e/specs/<screen>.spec.ts`, docs/18 §13): no retries, trace and screenshot only on failure (`test-results/e2e`, HTML report in `playwright-report/e2e`). `e2e/fixtures/fixtures.ts` checks after every test that `window.__xss` is undefined and that no dialog, page error, console error, CSP violation or request to another origin happened. The fixture option `ignoredConsoleErrors` (regular expressions, default none, `test.use({ ignoredConsoleErrors: [...] })`) exempts matching console errors; it is meant for positive controls only, and each exempted message is listed in an `ignored-console-error` annotation. With the suite's own preview the fixture also requires a `Content-Security-Policy` header on every main-frame document, so "no CSP violation" is checked under the preview policy; against `ARGOS_UI_BASE_URL` the header is not required and the test gets a `csp-not-verified` annotation. `e2e/specs/global-hooks.spec.ts` holds the positive controls: an injected inline script must be blocked and recorded as a violation, and the hook check must reject it. Chrome also logs the blocked script as a console error, so the controls exempt exactly that message: one test checks that, with the exemption, the recorded violation is the only failing check (clearing it makes the check pass), and the fixture-level control (`test.fail()`) therefore fails only through the fixture's CSP violation check — if the fixture stopped checking violations, that test would pass and Playwright would report it. Console errors the option does not match must still be rejected, and a document without the header must be rejected. `xlog-poc.spec.ts` drags on `/xlog-poc` and compares the selection summary and list with the expected points, which `e2e/fixtures/xlogOracle.ts` computes from the same seeded generator in Node.
- **Performance** (`playwright.perf.config.ts`, `perf/xlog-frame.spec.ts`): static 10k/50k/100k points (consecutive full redraws), static 100k with the slowest configuration (y = log, colour = service), realtime 100k + 500 points/s, hover/drag over 100k points (plus a second, not judged trace around the end of the drag), and 100k full-plot drag selections (selection, summary and React commit times, not judged here; the ADR-0003 C-36 budgets for them are judged in WO-33). Every scenario runs at each devicePixelRatio of `XLOG_PERF_DPR` (default 1 and 2; titles carry `dpr=<n>`). Each scenario warms up and measures at least 3 runs; before each run it samples the machine CPU load and waits up to `XLOG_PERF_MAX_WAIT` seconds for it to drop to `XLOG_PERF_MAX_LOAD` %. The per-frame time is the busiest rendering-pipeline thread (renderer main, compositor, GPU main, display compositor) per frame in a Chrome trace (`perf/lib/frames.ts`); the spec passes a scenario when the p95 and the mean of the frames of all its runs together are at most 16 ms. ADR-0003 C-35 judges each run instead (pooled values are for reporting); read that verdict from the summary table's highest single-run p95 and mean (`Max run p95`, `Max run mean`), which must both be at most 16 ms. A run whose trace lacks the renderer main thread or the GPU thread (`CrGpuMain`, or `Chrome_InProcGpuThread` with an in-process GPU), or in which Chrome reported trace data loss, fails a judged scenario whatever its numbers (`measurementProblems` in `perf/lib/frames.ts`). Results: `perf/results/xlog-frame-<time>.{jsonl,json,md}` and `xlog-frame-latest.*` (git-ignored). Settings (environment variables, see `perf/lib/settings.ts`): `XLOG_PERF_POINTS`, `XLOG_PERF_RENDER` (`default`, `path`, `rect`, `pixels`), `XLOG_PERF_SCENARIOS`, `XLOG_PERF_DPR`, `XLOG_PERF_COLOR`, `XLOG_PERF_Y`, `XLOG_PERF_POINT_CAP`, `XLOG_PERF_RUNS` (≥ 3), `XLOG_PERF_FRAMES`, `XLOG_PERF_LIVE_SECONDS`, `XLOG_PERF_MAX_LOAD`, `XLOG_PERF_MAX_WAIT`, `XLOG_PERF_COMPARE=1` (adds a realtime run with `incremental=0`, not judged), `XLOG_PERF_HEADED=1`, `XLOG_PERF_OUT`, `XLOG_PERF_EXPECT_GPU` (a case-insensitive part of the WebGL renderer string, e.g. `Radeon`: a run on another GPU fails the judged scenarios; hybrid-GPU laptops can switch between the integrated and the discrete GPU). Method and results: [docs/poc/xlog-ui.md](../docs/poc/xlog-ui.md).
