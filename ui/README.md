# Argos APM web UI

React + TypeScript (strict) + Vite, managed with pnpm. Design: [docs/15-ui-design.md](../docs/15-ui-design.md); build rules: [docs/19-repo-build-release-design.md](../docs/19-repo-build-release-design.md) §4–§5.

## Requirements

- Node.js 24 LTS (`.nvmrc`; `package.json#engines` requires `>=24.14.0 <25`, enforced by `engineStrict`)
- pnpm through Corepack (bundled with Node.js 24). The exact pnpm version is pinned in `package.json#packageManager` and in `pnpm-lock.yaml`.

```sh
corepack pnpm install --frozen-lockfile
```

From the repository root:

- with a standalone pnpm on `PATH` (for example installed by `pnpm/action-setup`), `pnpm -C ui build` works; pnpm switches itself to the pinned version;
- Corepack picks the pnpm version from the `package.json` of the _current_ directory (the root has none), so either run it inside `ui/` or name the version: `corepack pnpm@12.14.0 -C ui build`.

## Bundle size (docs/15 §14)

`corepack pnpm build` ends with `scripts/bundle-size.mjs` (also `corepack pnpm bundle:size` after a build, and so part of `:ui:pnpmBuild` and the CI build). It prints a table and writes `build/bundle-size.json`. The numbers are a reference: a budget overrun prints a `WARN` line and the script still exits 0. It exits 1 when it cannot measure: no chunk graph, a graph that does not match `dist/` (stale), or a module of the initial path that is in no chunk; and when a production chunk holds a module of the XLog proof of concept (`POC_MODULE_PREFIXES`, `src/features/xlog-poc/`; the report prints `PoC modules in production chunks: <n> (ADR-0010 C-203)`).

- Chunk graph: the `bundleGraph()` plugin in `vite.config.ts` writes `build/bundle-graph.json` on every production `vite build` (files, static and dynamic imports, CSS per chunk, project modules per chunk). It lives outside `dist/`, so it never ships in the server jar. Another build mode writes its own file (the perf build: `build/bundle-graph-perf.json`, with the `/xlog-poc` chunk that the production graph must not have, ADR-0010 C-203), so a perf build next to a production build never replaces the graph the report reads.
- Initial path (budget 350 KiB gzip): the first screen after login. The entry chunk of `index.html`, the chunks holding the lazy routes a signed-in user passes on the way to `/overview` (`INITIAL_LAZY_MODULES`: `src/app/AntdRoot.tsx`, `src/routes/AuthGate.tsx`, `src/routes/Shell.tsx`, `src/routes/ScreenRoute.tsx` with the `route-pending` placeholder; and `src/features/xlog/index.ts`, the XLog screen, which deep links open as the first screen, WO-33), the transitive closure of their static imports, and the CSS Vite loads with any of these chunks. The login page is not part of it. WO-31 adds the overview screen module to `INITIAL_LAZY_MODULES` (docs/15 §14 counts the shell and the overview chunk). With the XLog screen the initial path is over the budget (2026-11-15: 409.2 KiB gzip, 343.5 KiB without it; a PM decision is pending, WO-33 report). Since the lazy locale namespaces and the on-demand CSV helper (ADR-0010 C-209, WO-32) it is 359.1 KiB gzip / 367.5 KiB sent (before: 372.3 / 380.0 KiB; shared laptop, reference values). The dashboard screen is not on the initial path; its chunk is about 102 KiB raw / 37 KiB gzip plus 2.5 KiB CSS and its catalogs (about 1.3 / 1.5 KiB gzip for en / ko).
- Locale catalogs (ADR-0010 C-209): `common`, `shell` and `auth` are bundled into the entry (`bundledResources` in `src/i18n/resources.ts`); the screen namespaces (`xlog`, `tx`, `trace`, `dashboard`) are same-origin chunks that `src/i18n/lazyBackend.ts` loads through an `import.meta.glob` fixed at build time (no new dependency, no other origin). `routeTree.tsx` loads a screen's namespaces (`ROUTE_NAMESPACES` in `src/i18n/routeNamespaces.ts`) together with `screen.load()`, so a screen renders only with its text; a failed or missing catalog falls back to English without retries, and a language switch loads the new language of every loaded namespace before it applies. The app uses `createAppI18n`, tests `createI18n(language)` (eager, every catalog synchronously). A new screen namespace is registered in `ROUTE_NAMESPACES`; `routeNamespaces.test.ts` walks each route's module graph and fails when a module uses a namespace the table does not load, and `lazyLoading.test.tsx` keeps the bundled list and the lazy glob in step. `exportCsv` is imported on the first export.
- Total (budget 2.5 MiB = 2,560 KiB gzip): every JS and CSS file in `dist/`.
- Sizes are the gzip size of each file on its own (Node `zlib`, default level, like Vite's own report).
- Sent sizes (`sent` column and lines, `sent` in the JSON; ADR-0010 C-190): what the server puts on the wire for a browser that accepts gzip. Its response compression (`server.compression` in `server/src/main/resources/application.yml`) gzips JavaScript and CSS of 2 KiB (2,048 bytes) or more and sends smaller files as they are, so a file counts with its gzip size from 2,048 bytes and with its raw size below. They are compared with the same budgets (an overrun warns). The server's gzip is the JDK deflater at its default level, so the numbers are an estimate within a few bytes per file.
- Caching (C-190): the hashed files below `/assets/` are served with `Cache-Control: max-age=31536000, public, immutable`; `index.html` (a new CSP nonce per response) and the API stay `no-store`. There are no pre-compressed `.gz`/`.br` files.

## Rules enforced by the tooling

- `src/` holds only `.ts`/`.tsx` sources (including `.d.ts`), static assets (CSS, JSON, images, fonts) and documentation (`.md`, never imported, e.g. `src/security/untrusted.md`): `scripts/src-extensions.test.mjs` fails on `.js`, `.jsx`, `.mjs`, `.cjs`, `.mts`, `.cts`, any other file type, or an import of a `.md` file. The ESLint rules below cover all of these script extensions under `src/` as well.
- Every TS/JS file starts with `// SPDX-License-Identifier: Apache-2.0` (`argos/spdx-header`).
- User-facing text comes from `src/locales/<lang>/<namespace>.json` through i18next; English is the source, Korean the translation. Literal strings in JSX text and user-visible attributes fail `i18next/no-literal-string`. Keys are type-checked by `tsc`.
- Translation keys follow docs/15 §12: `<ns>:<area>.<element>`. A key without a prefix is looked up in `common` only, so keys of every other namespace are written with their prefix: `useTranslation(['common', 'xlog'])` and `t('xlog:summary.title')`, not `useTranslation('xlog')` and `t('summary.title')`. Pass the namespaces as an array: i18next's types accept a `<ns>:` prefix only then. `check:i18n` fails an unprefixed key that is not in `common` and says which prefix to use.
- `check:i18n` expects the catalogs of the languages in `src/i18n/resources.ts` (`--languages`, default `en,ko`; a test keeps the two in sync). A missing language directory or namespace file is a warning, and an error with `--release`.
- Untrusted strings reach the DOM only as React text nodes (SEC-60): `react/no-danger` on DOM elements and components, and `no-restricted-syntax` for `dangerouslySetInnerHTML` in any form (JSX attribute, spread or `createElement` props object, member access), `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `createContextualFragment`, `setHTML`/`setHTMLUnsafe`/`parseHTMLUnsafe`, `DOMParser`/`parseFromString`, `document.write`, `eval`, `Function`, `srcdoc` (JSX attribute or property) and `setAttribute` of `srcdoc` or `on*` event handler attributes.
- `fetch`/`XMLHttpRequest` only in `src/api`, `WebSocket` only in `src/realtime`, `EventSource` and `navigator.sendBeacon` nowhere (a beacon would POST without `X-Argos-CSRF`, SEC-43), Ant Design only in `src/components` and `src/app`, uPlot only in `src/charts`, the generated API types and `openapi-fetch` only in `src/api`, and `zod` only in `src/app` (everything else imports `z` from `src/app/zod.ts`, which turns zod's JIT off: zod 4 probes `new Function`, which the server CSP without `'unsafe-eval'` reports as a violation). This covers static imports (`no-restricted-imports`) and `import()` with a literal module name (`no-restricted-syntax`).
- Collected strings are typed `Untrusted` (branded, from `x-argos-untrusted` in the contract) and reach JSX only as `<SafeText value>`, `<CodeBlock value>` or `<SafeLink href>` (`argos/untrusted-text`, type-aware; templates, `String()`, string methods, member access on derived text such as `value.split('/')[0]`, calls that return text such as `JSON.stringify({ n: value })` or `Array.from(value).join('')`, `as` casts and i18n interpolation `t('key', { name: value })` are caught too). Checklist: [src/security/untrusted.md](src/security/untrusted.md).
- Link targets (`href` of DOM elements and Ant Design link components) are internal path literals or `safeHref(…)` (`argos/no-raw-href`).
- No `blob:` object URLs (`URL.createObjectURL`, `argos/no-object-url`): downloads go through `saveFile()` of `src/api/exportCsv.ts`, the one file exempt in `eslint-allow.json`.
- Browser storage holds preferences only: `localStorage`/`sessionStorage` with literal `argos.ui.*` keys, no cookie writes, no IndexedDB (`argos/no-token-storage`, SEC-40). The session lives in httpOnly cookies.
- Production code imports only packages listed in `dependencies`.
- Inline `eslint-disable` comments are ignored in `src/`. Exceptions are listed per file, with a reason, in `eslint-allow.json`.
- Bundled packages must be licensed under Apache-2.0, MIT, MIT-0, BSD-2-Clause, BSD-3-Clause, ISC, 0BSD, PostgreSQL, Unicode-DFS or CC0-1.0 (`scripts/license-policy.json`).
- The bundle never references another origin: no external `src`/`href`/`url()`/`@import`, and no absolute URL in any script, stylesheet or markup, also not escaped (`https:\/\/…`) or as a protocol-relative string (`"//host/…"`). Exact URL strings that are never fetched (XML namespaces, links in library error messages) are listed with a reason in `scripts/external-allowlist.json`; escaped URLs are matched in their unescaped form.

## URL state (docs/15 §4, DSN-14-17, ADR-0010 C-166)

`src/state/urlState.ts` parses and writes every shared state of a screen. The writer emits only the docs/14 §6 form (DSN-14-17): `from`/`to` (`now-15m`, `now/d`, ISO-8601 UTC), `kind`, `f.<field>=value` (equals; several values of one field mean "any of them"), `f.<field>=!value` (exclude; a value starting with `!` or `\` gets a leading `\`), `sel=ms:<min>-<max>,ts:<from>-<to>`, `live=1`, `kiosk=1`, `env`, `tab`, …

- Extension (PM decision pending): `f.<field>.<op>=value` with `op` = `gt`, `gte`, `lt`, `lte` or `contains` is a WO-30 extension of DSN-14-17 for column range and text filters (docs/15 §6.3). It is not part of the canonical grammar shared with the alert deep links (WO-25), and server deep links must not emit it until the PM decides. The UI writes it only for those operators.
- The reader also accepts the docs/15 §4.2 forms and normalises them: `range=<preset>`, epoch milliseconds, `f=<field>:<op>:<value>` (op `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `contains` or `in`; `f=status:in:500,503` becomes `f.status=500&f.status=503`), `sel=<t1>,<t2>,<y1>,<y2>`, `kind` in any case.
- Detail and trace keys (WO-34): `TxDetailQ` has `ts` (the ADR-0007 C-50 lookup hint), `tab`, `compare` and `back` (the XLog path and query a detail link came from, ADR-0010 C-206 (1); kept only when it is a same-origin path by the `safeNextPath` rules). `TraceQ` has `ts` and `window` (`1h`, `24h`, `7d`, `30d`, docs/14 §4.7; absent = the server's rule: ±1 h around `ts`, else 24 h).
- Every item is validated on its own; an invalid one falls back to its default and shows `url-restore-notice` once. Limits: query ≤ 8 KB read, URL ≤ 2 KB written, ≤ 20 filters (each value of an `in` list counts), filter and search values ≤ 1,024 UTF-8 bytes like the server (`utf8ByteLength`, `fitsFilterValue`; 341 Hangul syllables fit, 342 do not).

## Adding a screen (WO-31..39)

1. Put the screen in `src/features/<screen>/<Screen>.tsx` and add one line to its entry in `src/routes/screens.ts`: `load: () => import('../features/<screen>/<Screen>').then((m) => m.<Screen>)`. Route, permission guard (`route-forbidden`), URL loader, side menu entry and `g` shortcuts already work; the placeholder disappears.
2. URL state: `useUrlState(<Schema>)` (`state`, `issues`, `set(partial, { replace?, pathname? })`, the only URL writer; 2 KB write limit). Screen keys extend `CommonQ` with the field helpers of `urlState.ts`. Time range: `useTimeRange()` (`range`, `live`, `liveAvailable` from the screen entry's `live` flag, `sel`, `resolved`, `queryRange`, `dispatch(action)`), REST refill after "resume live" with `useResumeResync`. Keyboard: `t` then `1`–`9` picks a preset (docs/15 §5).
3. Data: an API function in `src/api/<resource>.ts` (the generated types are importable only inside `src/api`), `unwrap(api().client.GET('/api/v1/…', …))` gives `{ data, meta }`; query keys from `queryKeys.screen('<screen>', { appId, range: time.queryRange, … })`. 64-bit ids stay strings (C-175). Show `meta.truncated`, `meta.retention_exceeded` and `meta.sampling` with `PartialBanner`, errors with `ErrorState` (`errorInfo(error)`), `null` values as `—` (never 0).
   Tables (common API of the screen work orders):
   - CSV: `exportCsv(method, path, request)` in `src/api/exportCsv.ts` from `DataTable`'s `onExportCsv`. It accepts only contract operations that answer `text/csv` (type-checked), sends `format=csv` (and `tz`, default the browser zone) through the shared transport (cookies, `X-Argos-CSRF` on POST, one refresh on 401) and saves the file under the sanitised Content-Disposition name. A 429 is an `ApiError` with `retryAfterSeconds`: show the retry hint, never retry in a loop (C-176). The UI never builds a CSV (DSN-15-06). Its `saveFile()` is the only place allowed to create object URLs (`argos/no-object-url`); a Blob of type `application/json` is saved with a `.json` name (`jsonFileName`, `sanitizeJsonFileName`; the transaction export of the server and the trace JSON of ADR-0010 C-207 (1)), any other with `.csv`.
   - Sort: `sortSpecToUrl(sort)` / `urlToSortSpec(state.sort)` in `src/state/sort.ts` convert `DataTable`'s `{ id, desc }` to and from `sort=field:asc|desc`, the URL and API form.
   - Filters: `src/state/filters.ts` turns a `FilterChipBar`/`DataTable` filter (column filter, cell include/exclude) into URL state (field pattern, 1,024 UTF-8 bytes per value). `toUrlFilter(spec)` gives one filter (single filters only: an `in` list with one value becomes `eq`, a list with several values or an empty item gives `null`). `toUrlFilters(spec)` gives the list: `in` (`a,b`) expands to one `eq` per value with the same rule as the URL reader (`splitInList` in `urlState.ts`; `null` for an empty item, a value over 1,024 bytes or more than 20 values); keeping the total at or under 20 filters is the caller's job. Write the list with `useUrlState().set({ filters })`.
   - Cell include/exclude (`filterable` columns, `onCellFilter`): a column with `filterValue` uses only `filterValue(row)`; when it returns `null`/`undefined` that cell has no include/exclude (no buttons, no cell menu), and the shown value never stands in for the key under its `filterField`. A column without `filterValue` uses the shown `value(row)`. The value is passed as is and never cut. A value over 1,024 UTF-8 bytes (SEC-64) cannot be a filter: `cell-filter-include`/`cell-filter-exclude` and both items of the cell menu are disabled (`disabled`, `aria-disabled="true"`), say why in `title` and `aria-describedby`, and the menu shows `data-table-cell-too-long`; the keyboard path (Shift+F10, context menu key) behaves the same. For columns of long collected strings (SQL text, URLs, error messages), give a short key through `filterValue` (an id such as `sql_id`) with its `filterField`.
4. Live data: `useTopic(topic, params | null, { onData, onResync, onError })`; the shell already subscribes `counter` / `overview` and shows `ws-stale-badge`.
5. Strings: i18n keys only (`<ns>:<area>.<element>`, `en` and `ko`; a new namespace gets its catalogs in `src/locales/<lang>/`, its type and name in `src/i18n/resources.ts` (`Catalogs`) and its route entry in `ROUTE_NAMESPACES` of `src/i18n/routeNamespaces.ts`, see [Bundle size](#bundle-size-docs15-14)). Collected strings only through `SafeText`, `SafeLink`, `CodeBlock`.
6. E2E: add `e2e/required/<screen>.yaml` (format in [e2e/README.md](e2e/README.md#required-elements-e2erequired)) and `defineRequiredTests('<screen>')` in `e2e/specs/required.spec.ts`; manifest variables (absolute range, representative ids, window totals) are in `e2e/required/variables.ts`.

## XLog transaction list and the detail (WO-33, ADR-0010 C-202, C-206)

- **One conversion.** `toTransactionSearchRequest(appId, xlogQuery, cursor?)` in `src/api/transactionSearch.ts` turns the XLog URL state (`XLogQ`: `time`, `kind`, `filters`, `sort`, `sel`) into the `POST /apps/{appId}/transactions/search` call: range and elapsed bounds from `sel` (inclusive, so `to` = `tsTo + 1`; the resolved time range without a selection), `kind`, the f= filters, `sort` `elapsed_ms:desc` (default) or `ts:desc`, `limit` 1,000 and the keyset `cursor`. It returns `{ appId, body, unapplied, empty }`: `unapplied` lists the URL filters the API cannot express (exclusions `!value`, unknown fields, invalid keys, several values of a single-valued field) and the screens show them, never emulate them; `empty` means the conditions can match nothing. `toXlogPointFilters(filters)` and `toXlogSummaryRequest(appId, xlogQuery)` give the same vocabulary for `GET /xlog` and `POST /xlog/summary` (service, instance, error and elapsed only). The XLog list and the detail's previous/next (WO-34) both use it.
- **Filter vocabulary** (docs/14 §6, values are keys, never names; 64-bit keys stay decimal strings, C-175): `f.service` (service key), `f.instance` (instance id), `f.status` (HTTP status), `f.error_class` (error class key), `f.version` (version key), `f.error` and `f.profile` (`true`/`false`), `f.user`, `f.request`, `f.trace`, `f.sql`, `f.error_group`, `f.remote_ip`, and `f.elapsed_ms.{gt,gte,lt,lte}`. A summary row click toggles `f.service`, `f.instance`, `f.error=true`, `f.status` or `f.error_class` and keeps `sel` (C-202 (2)); a list cell's include/exclude writes the same fields (an included kind sets the global `kind`).
- **Detail links.** `transactionDetailUrl(appId, txId, ts, back)` in `src/features/xlog/list/detailLink.ts` (list rows, Enter, point clicks) gives `/apps/:appId/transactions/:txId?ts=<ISO-8601 UTC>&back=<XLog path + query>`; the whole link stays within the 2 KB write limit (a `back` without the view-only keys `cols`, `color`, `y`, `live`, `kiosk`, `alert` first, no `back` as the last resort, which the detail shows as disabled previous/next).
- **List context.** Opening a row stores the list's order in memory (`saveListContext`, `src/features/xlog/list/listContext.ts`; at most 8 lists of at most 1,000 rows, no browser storage): `listNeighbours(back, txId)` gives `{ index, previous, next, moreAfter }` (`previous`/`next` are `{ txId, ts }`; `moreAfter` with the context's `nextCursor` asks for the page after the last row), and `getListContext(back)` the whole entry (`query`, `rows`, `total`, `nextCursor`). Without an entry (reload, another tab, a shared link) the detail re-queries `back` with `toTransactionSearchRequest` (C-206 (2)): the URL stays the source of truth.
- **Preview (ADR-0010 C-204, ADR-0003 C-36).** While the first page of a new selection is on its way, `TxListPanel` (prop `preview`: the page's buffer and dictionary, `applicable` when the points are those of the current range, kind and filters and the points API applied every filter, `sampled`, `truncated` and `slowThresholdMs` of the response's `meta`) shows the first 20 rows from the chart's own points in the server's order (`src/features/xlog/list/previewRows.ts`: `elapsed_ms`, `ts`, `tx_id` descending, or `ts`, `tx_id` descending; `tx_id` unsigned) when they are exactly the server's first rows: every row of an unsampled response; of a sampled one (A-5 keeps every error and slow point) only the leading rows at or above the threshold in the response time order; none for a truncated response, unknown sampling facts or the time order of a sampled one: `data-state="preview"`, the columns the points do not carry (HTTP status, error class, SQL, outgoing calls, user, profile, version) as a pending mark (`xlog-list-pending`, never the missing dash), no CSV, no list context. The server rows replace them (`data-state="ready"`). Tests that compare rows with the server wait for `data-state="ready"` (or `data-rows`).
- **CSV** of the list is the server export of the same search (`exportTransactionsCsv`, `format=csv`, HEAVY bucket and `EXPORT_CSV` audit, at most 10,000 rows, C-205 (1)); a 429 shows the Retry-After hint without retrying. The transaction search is in the HEAVY bucket (10 per user per minute): the E2E specs ask their expectation queries as another user than the browser's.

## Transaction detail and trace view (WO-34, ADR-0010 C-206, C-207)

- **Routes.** `/apps/:appId/transactions/:txId` (`src/features/transaction/TransactionPage.tsx`) and `/traces/:traceId` (`src/features/trace/TracePage.tsx`), both lazy. The `/tx/:txId` alias looks the transaction up and replaces the URL with the app route, keeping `ts`, `tab`, `compare`, `back` and the global keys; it stores the detail it fetched under the detail's query key (`primeTransaction`), so the server is asked (and audits) once. A transaction of another application moves to that application's route (C-166).
- **Data** only through the generated client. `src/features/transaction/data`: `useTransaction(txId, ts)` gives `invalid`, `pending`, `not_found` (`reason` `clock_skew_possible` or `not_found`, `hinted`), `error` (`ErrorState`) or `success`; `useTransactionBaseline(txId, detail.ts)`; `downloadTransactionExport(txId, ts)` saves the server's `GET /transactions/{txId}/export` bytes (audited, C-176 (1)). `src/features/trace/data`: `useTrace(traceId, ts, window)`; `saveTraceJson(response)` saves the received response through `saveFile` (C-207 (1)). A `null` or `measured=false` value renders the dash or "not measurable", never 0 (D-23); `profile.state` (`sampled_out`, `lost`) and `params_mode` (`masked`, `partial`, `full`, `masked_by_role`) are shown as the server sent them (D-07, C-13).
- **Navigation.** Links carry the ADR-0007 C-50 `ts` hint and the time range of their context. The statistics, trace and caller links of a detail use the range of the XLog list in `back`, else the detail URL's own `from`/`to`, else ±30 minutes around the transaction in whole minutes with its kind. A trace node opens its detail with the trace URL's range (detail → trace → detail keeps it); an application opens its dashboard for the searched window (absolute range, live off). Back to the list returns to `back`. Previous/next take the neighbours from the XLog list context in memory (`listNeighbours`) or re-query `back` with `toTransactionSearchRequest` (first page); without a usable `back` they are disabled and say why. The copied link is the app route with `ts` and a non-default `tab`, never `back`. A transaction that is not found (ADR-0007 C-50) offers the list of `back`, the XLog of ±15 minutes around the `ts` hint (or the time in the id; kind ALL, environment kept) and the XLog with the detail URL's carried keys; the `/tx/:txId` alias says the same, without the `ts` advice when the link already had a hint.
- **Waterfall** (`src/components/waterfall`, DSN-15-11: DOM rows, no SVG or Canvas), shared by the timeline, the call tree and the trace view:
  - `VirtualRows<T>({ items, getKey, label, renderRow(item, index, focused), getMeta?, onActivate?, onExpandedChange?, renderTooltip?, header?, role?, maxHeight?, rowHeight?, overscan?, labelWidth?, focusedIndex?, onFocusedIndexChange?, rowTestId? })`: TanStack Virtual rows of 24 px (default height 480 px, overscan 10) in a `treegrid` with `aria-rowcount`, `aria-level` and `aria-expanded` from `getMeta` (`{ level, expanded, selected }`), a roving tab index and the keys ↑ ↓ Home End PageUp PageDown → ← Enter.
  - `WaterfallRow({ depth, name, icon?, trailing?, startMs, elapsedMs, totalMs, tone, dashed?, variant?, markerLabel?, markerKind?, segments?, markers?, emphasis?, error? })`: two grid cells (indented name, bar). `segments` are grey parts `{ startMs, elapsedMs, kind: 'self' | 'wait' }` (uninstrumented time, network / wait), `markers` icons at an offset `{ offsetMs, kind: 'stack' | 'error', label }` (STACK captures, the ERROR records of a folded run), `variant: 'marker'` a row drawn as one icon at its start (a STACK step, a folded run of STACK or ERROR records; `markerKind` picks the icon, default `stack`), `variant: 'none'` an empty track (a SUMMARY step), `emphasis: 'critical'` the critical path. Positions are set through React `style` only (CSP); a bar is at least 2 px and a clipped bar is marked, never hidden.
  - `TimeScale({ totalMs, maxTicks?, label? })` and the helpers `timeScale`, `unitFor` (ms, s, min from 2 minutes), `barGeometry`, `timelineTotal`, `stepTone(type)` (docs/15 §13 step tokens; `COMMIT`/`ROLLBACK` as SQL, `MESSAGE` as HTTP, unknown types as METHOD).
- **Models.** `src/features/transaction/model`: `buildTree`/`collapseRepeats` (consecutive siblings with the same type + nameId (`sql_id` for SQL) + target, runs of 3 or more, every level, folded by default, DSN-15-12), `selfTime` (union of the children clipped to the parent; the server's `self_time_ms` first, highlighted from 20 %), `calls`, `stacks`, `links`. `src/features/trace/model/traceTree.ts`: parent links, external nodes under their caller, both missing kinds, the server's `critical_path` first, the caller step against the callee with the network / wait part (D-05; a caller shorter than its callee shows both values and a D-05 mismatch note that claims no cause, never a negative bar). The response has no start of the caller step or of an external call: their bars are placed by duration and labelled as estimates.

## Application dashboard (WO-32, ADR-0010 C-160, C-177, C-178, C-209)

- **Route.** `/apps/:appId/dashboard` (`src/features/dashboard/DashboardPage.tsx`, lazy, namespace `dashboard`), the default screen of an application; also in the kiosk layout.
- **Requests** (`src/api/dashboard.ts`, `features/dashboard/data/plan.ts`): `GET /apps/{appId}/dashboard` with the absolute `from`/`to`, `kind` (only when not HTTP), `instance[]` from the `f.instance` include filters (at most 100) and `baseline` (`none`/`1d`/`7d`). The server gives the tile change against 7 days only with `baseline=7d`, so a second, tiles-only request is sent only when `tileRef` and `baseline` do not match (`tileRef=prev` with `baseline=7d`, `tileRef=7d` with `baseline` none or 1d): at most two requests. Exclusions (`f.instance=!id`) and other fields are listed as not applied, never emulated. A relative range is resolved on a 60-second clock (D-03: re-queried every minute), on a 5-second clock while polling. The comparison table asks `GET /instances/compare` (CSV through its `format=csv`); the excluded-request reasons ask `GET /collection-health` only when the count is above 0.
- **Charts.** Nine `TimeSeriesChart`s sharing `syncKey='dashboard'`: TPS, response time avg/p95/p99, error rate, active, heap used/max + GC pause, process CPU, Tomcat thread usage, pool usage per pool (pool names are untrusted text), external call time and errors. The baseline is a dashed series on the transaction charts. Events are markers (`alert=` emphasises its event), `outages` shade every chart with the legend "N collection gaps" (T-ACC-18 display). Drag sets an absolute range and switches live off; a point click opens XLog ±max(range/60, 1 min) around the bucket with kind and environment. Panel notes say what the API cannot give yet: active is not measurable before WO-22 (C-178), CPU is the process only, no pools, no external error source.

## End-to-end and performance tests (Playwright)

Playwright (`@playwright/test`, Apache-2.0, a devDependency) drives Chromium; the suites are separate from `test` because they need a browser and a build. Install the browser once per machine (it goes to the Playwright cache, `%LOCALAPPDATA%\ms-playwright` on Windows, `~/.cache/ms-playwright` on Linux):

```sh
corepack pnpm playwright:install      # = playwright install chromium (Linux CI: add --with-deps)
corepack pnpm e2e                     # vite build + E2E projects preview and stack
corepack pnpm e2e:docker              # stack project in the pinned Linux image (screenshot baselines)
corepack pnpm perf                    # vite build + XLog frame-time spec (about 12–16 minutes)
corepack pnpm perf:initial-load       # initial load against the stack (reference values)
```

**Stack E2E (WO-30, docs/18 §13).** The `stack` project runs every WO-30 spec against the server boot jar of this tree, with PostgreSQL and ClickHouse containers on random `127.0.0.1` ports (label `io.argos.e2e`, name prefix `argos-e2e-`, at most 5 GiB with the Playwright container, always removed). Build the jars first, from the repository root: `./gradlew :server:bootJar :agent:agent-dist:agentJar :sample-apps:shop-boot3:sampleAppJar :sample-apps:ext-stub:sampleAppJar :sample-apps:smoke:sampleAppJar` (the stack refuses a server jar older than the UI or server sources). It needs Docker, JDK 21 on `JAVA_HOME` and, on Windows, Git Bash. The seed is deterministic (generator seed 42, profile tiny, anchored on the current UTC day, C-170): `:server:loadQueryTestData` data and PostgreSQL metadata, three users (admin, operator, viewer), shop-boot3 with the agent and `test/seed/seed-traffic.sh` through gRPC. The seed manifest `ui/e2e/.stack/seed-manifest.json` gives the specs the absolute range, representative ids and window totals; specs assert exact values from it or from an API query, never "at least one". The WebSocket endpoint is the only stub (`page.routeWebSocket`, docs/14 §5, until WO-22). CSP (SEC-46, ADR-0010 C-188): every stack test fails on any `securitypolicyviolation` event under the server's nonce policy, in the page's current document (page hooks) and in every other document of its browser context, also one left by a navigation or another tab (`contextCsp` of `e2e/fixtures/stack.ts`); the positive controls in `e2e/specs/csp-report.spec.ts` cause a real violation on a stack page and must see it. Screenshot baselines (`e2e/specs/__screenshots__/`) are created and compared only in the pinned Linux image (`e2e:docker`); elsewhere those tests are skipped with the annotation `screenshot-linux-only`. Everything else (variables, projects, fixtures, required YAML, troubleshooting): [e2e/README.md](e2e/README.md).

The `preview` project and the frame-time suite (PoC target) serve the perf build in `build/perf-dist/` with `vite preview` on `127.0.0.1:4319` (`ARGOS_UI_PORT` changes the port). The preview sends the Content-Security-Policy of docs/16 §9.9 (SEC-46) without its nonce and report parts (`preview.headers` in `vite.config.ts`; the dev server sends none). `ARGOS_UI_BASE_URL=http://host:port` runs them against a server that is already running instead (for example `corepack pnpm dev`), without starting one. Viewport 1366×768, locale `en-US`, Chromium in new headless mode (`channel: 'chromium'`). The E2E suite runs at devicePixelRatio 1; the performance spec runs every scenario at each ratio of `XLOG_PERF_DPR` (default 1 and 2).

The `e2e`, `e2e:preview` and `perf` scripts build first (`vite build --mode perf --outDir build/perf-dist`: the `/xlog-poc` route exists only in that build, ADR-0010 C-203, and a production build into `dist/` cannot replace it mid-run); the suites themselves serve that build as it is (the `stack` project and the `XLOG_PERF_TARGET=route` perf runs use the UI of the server boot jar instead). When you run `corepack pnpm exec playwright test` directly, run that perf build first: the global setups (`e2e/fixtures/globalSetup.ts`, `perf/lib/globalSetup.ts`) fail when `build/perf-dist/index.html` is missing, older than the newest file of `src/`, `index.html`, `vite.config.ts` or `package.json`, or a production build without the `/xlog-poc` chunk (`perf/lib/pocBuild.ts`; not checked with `ARGOS_UI_BASE_URL`).

- **E2E** (`playwright.config.ts`, `e2e/specs/<screen>.spec.ts`, docs/18 §13): no retries, one worker, trace and screenshot only on failure (`test-results/e2e`, HTML report in `playwright-report/e2e`). `e2e/fixtures/fixtures.ts` checks after every test that `window.__xss` is undefined and that no dialog, page error, console error, CSP violation or request to another origin happened. The fixture option `ignoredConsoleErrors` (regular expressions, default none, `test.use({ ignoredConsoleErrors: [...] })`) exempts matching console errors; it is meant for positive controls only, and each exempted message is listed in an `ignored-console-error` annotation. With the suite's own preview the fixture also requires a `Content-Security-Policy` header on every main-frame document, so "no CSP violation" is checked under the preview policy; against `ARGOS_UI_BASE_URL` the header is not required and the test gets a `csp-not-verified` annotation. `e2e/specs/global-hooks.spec.ts` holds the positive controls: an injected inline script must be blocked and recorded as a violation, and the hook check must reject it. Chrome also logs the blocked script as a console error, so the controls exempt exactly that message: one test checks that, with the exemption, the recorded violation is the only failing check (clearing it makes the check pass), and the fixture-level control (`test.fail()`) therefore fails only through the fixture's CSP violation check — if the fixture stopped checking violations, that test would pass and Playwright would report it. Console errors the option does not match must still be rejected, and a document without the header must be rejected. The positive controls open `/xlog-poc` (the shell at `/` needs the server nonce, which `vite preview` does not inject). `xlog-poc.spec.ts` drags on `/xlog-poc` and compares the selection summary and list with the expected points, which `e2e/fixtures/xlogOracle.ts` computes from the same seeded generator in Node.
- **Performance** (`playwright.perf.config.ts`, `perf/xlog-frame.spec.ts`): static 10k/50k/100k points (consecutive full redraws), static 100k with the slowest configuration (y = log, colour = service), realtime 100k + 500 points/s, hover/drag over 100k points (plus a second, not judged trace around the end of the drag), and 100k full-plot drag selections (selection, summary and React commit times; on the PoC page measured, not judged: ADR-0003 C-36 is judged on the XLog screen, `XLOG_PERF_TARGET=route` below). Every scenario runs at each devicePixelRatio of `XLOG_PERF_DPR` (default 1 and 2; titles carry `dpr=<n>`). Each scenario warms up and measures at least 3 runs; before each run it samples the machine CPU load and waits up to `XLOG_PERF_MAX_WAIT` seconds for it to drop to `XLOG_PERF_MAX_LOAD` %. The per-frame time is the busiest rendering-pipeline thread (renderer main, compositor, GPU main, display compositor) per frame in a Chrome trace (`perf/lib/frames.ts`); the spec passes a scenario when the p95 and the mean of the frames of all its runs together are at most 16 ms. ADR-0003 C-35 judges each run instead (pooled values are for reporting); read that verdict from the summary table's highest single-run p95 and mean (`Max run p95`, `Max run mean`), which must both be at most 16 ms. A run whose trace lacks the renderer main thread or the GPU thread (`CrGpuMain`, or `Chrome_InProcGpuThread` with an in-process GPU), or in which Chrome reported trace data loss, fails a judged scenario whatever its numbers (`measurementProblems` in `perf/lib/frames.ts`). Results: `perf/results/xlog-frame-<time>.{jsonl,json,md}` and `xlog-frame-latest.*` (git-ignored). Settings (environment variables, see `perf/lib/settings.ts`): `XLOG_PERF_POINTS`, `XLOG_PERF_RENDER` (`default`, `path`, `rect`, `pixels`), `XLOG_PERF_SCENARIOS`, `XLOG_PERF_DPR`, `XLOG_PERF_COLOR`, `XLOG_PERF_Y`, `XLOG_PERF_POINT_CAP`, `XLOG_PERF_RUNS` (≥ 3), `XLOG_PERF_FRAMES`, `XLOG_PERF_LIVE_SECONDS`, `XLOG_PERF_MAX_LOAD`, `XLOG_PERF_MAX_WAIT`, `XLOG_PERF_COMPARE=1` (adds a realtime run with `incremental=0`, not judged), `XLOG_PERF_HEADED=1`, `XLOG_PERF_OUT`, `XLOG_PERF_EXPECT_GPU` (a case-insensitive part of the WebGL renderer string, e.g. `Radeon`: a run on another GPU fails the judged scenarios; hybrid-GPU laptops can switch between the integrated and the discrete GPU). Method and results: [docs/poc/xlog-ui.md](../docs/poc/xlog-ui.md).
- **Performance, XLog screen** (`XLOG_PERF_TARGET=route`, WO-33): the same spec against `/apps/:appId/xlog` of the E2E stack (the global setup starts and seeds it, or reuses `ARGOS_E2E_STACK_URL`; build the jars first, as for `e2e`). `XLOG_PERF_ROUTE_WINDOW` picks the seed window (default `generator-range`: more than 100,000 points in the window, the A-5 sample is drawn); scenarios `static` and `static-worst` (frames, C-35 per run; the notes give the drawn count of the server's sample), `realtime` (the docs/14 §5 WebSocket stub on `page.routeWebSocket`, `perf/lib/routeLive.ts`: 100,000 points backfilled into the live 5-minute window, then 500 points/s; frames as C-35; the real WebSocket server is WO-22), `interaction` (hover and drag frames) and `selection` with two variants, the full plot and a partial in-plot rectangle: per run the selection query p95 ≤ 5 ms, the screen's selection (`selectMs` of `window.__xlogPerf.lastSelection()`) p95 ≤ 5 ms and the screen reflect p95 ≤ 100 ms (ADR-0003 C-36). The reflect runs from the pointer release (`event.timeStamp`) to the first frame with the summary count and the list's first row painted, the largest of the page's paint time, the trace's Commit/Paint and the GPU frame (viz `DrawAndSwap`, else the renderer's `PipelineReporter`; Reflect (GPU) column). Preview rows count (ADR-0010 C-204, `perf/lib/reflect.ts` `ROUTE_SELECTORS`) only when the preview's first row is the server's first row; otherwise that sample counts the frame of the server's rows. The time to the server's rows and the mismatch count are reported in the run notes (not judged). `XLOG_PERF_ROUTE_UNSAMPLED=1` measures the longest unsampled window of 90,000 to 100,000 points instead of the sampled seed window; `XLOG_PERF_TRACE_DIR=<dir>` writes each measured selection's renderer trace events there (diagnostics, off by default). Selections are 6.5 s apart (the search is a HEAVY request, 10 per user and minute). The route run also reports three page loads of the window (response size, parse, buffer conversion, first frame; `window.__xlogPerf.lastLoad()`, installed only with the browser preference `argos.ui.xlogPerf` = `1`). Example: `XLOG_PERF_TARGET=route XLOG_PERF_SCENARIOS=static,interaction,selection corepack pnpm perf`. Numbers of a shared machine are reference values (INVALID); the C-35/C-36 verdict needs a quiet machine.
