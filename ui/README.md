# Argos APM web UI

React + TypeScript (strict) + Vite, managed with pnpm. Design: [docs/15-ui-design.md](../docs/15-ui-design.md); build rules: [docs/19-repo-build-release-design.md](../docs/19-repo-build-release-design.md) §4–§5.

## Requirements

- Node.js 24 LTS (`.nvmrc`; `package.json#engines` requires `>=24.14.0 <25`, enforced by `engineStrict`)
- pnpm through Corepack (bundled with Node.js 24). The exact pnpm version is pinned in `package.json#packageManager` and in `pnpm-lock.yaml`.

```sh
corepack pnpm install --frozen-lockfile
```

From the repository root:

- with a standalone pnpm on `PATH` (for example installed by `pnpm/action-setup`), `pnpm -C ui build` works; pnpm switches itself to the pinned version;
- Corepack picks the pnpm version from the `package.json` of the _current_ directory (the root has none), so either run it inside `ui/` or name the version: `corepack pnpm@12.14.0 -C ui build`.

## Bundle size (docs/15 §14)

`corepack pnpm build` ends with `scripts/bundle-size.mjs` (also `corepack pnpm bundle:size` after a build, and so part of `:ui:pnpmBuild` and the CI build). It prints a table and writes `build/bundle-size.json`. The numbers are a reference: a budget overrun prints a `WARN` line and the script still exits 0. It exits 1 only when it cannot measure: no chunk graph, a graph that does not match `dist/` (stale), or a module of the initial path that is in no chunk.

- Chunk graph: the `bundleGraph()` plugin in `vite.config.ts` writes `build/bundle-graph.json` on every `vite build` (files, static and dynamic imports, CSS per chunk, project modules per chunk). It lives outside `dist/`, so it never ships in the server jar.
- Initial path (budget 350 KiB gzip): the first screen after login. The entry chunk of `index.html`, the chunks holding the lazy routes a signed-in user passes on the way to `/overview` (`INITIAL_LAZY_MODULES`: `src/app/AntdRoot.tsx`, `src/routes/AuthGate.tsx`, `src/routes/Shell.tsx`, `src/routes/ScreenRoute.tsx` with the `route-pending` placeholder), the transitive closure of their static imports, and the CSS Vite loads with any of these chunks. The login page is not part of it. WO-31 adds the overview screen module to `INITIAL_LAZY_MODULES` (docs/15 §14 counts the shell and the overview chunk).
- Total (budget 2.5 MiB = 2,560 KiB gzip): every JS and CSS file in `dist/`.
- Sizes are the gzip size of each file on its own (Node `zlib`, default level, like Vite's own report).
- Sent sizes (`sent` column and lines, `sent` in the JSON; ADR-0010 C-190): what the server puts on the wire for a browser that accepts gzip. Its response compression (`server.compression` in `server/src/main/resources/application.yml`) gzips JavaScript and CSS of 2 KiB (2,048 bytes) or more and sends smaller files as they are, so a file counts with its gzip size from 2,048 bytes and with its raw size below. They are compared with the same budgets (an overrun warns). The server's gzip is the JDK deflater at its default level, so the numbers are an estimate within a few bytes per file.
- Caching (C-190): the hashed files below `/assets/` are served with `Cache-Control: max-age=31536000, public, immutable`; `index.html` (a new CSP nonce per response) and the API stay `no-store`. There are no pre-compressed `.gz`/`.br` files.

## Rules enforced by the tooling

- `src/` holds only `.ts`/`.tsx` sources (including `.d.ts`), static assets (CSS, JSON, images, fonts) and documentation (`.md`, never imported, e.g. `src/security/untrusted.md`): `scripts/src-extensions.test.mjs` fails on `.js`, `.jsx`, `.mjs`, `.cjs`, `.mts`, `.cts`, any other file type, or an import of a `.md` file. The ESLint rules below cover all of these script extensions under `src/` as well.
- Every TS/JS file starts with `// SPDX-License-Identifier: Apache-2.0` (`argos/spdx-header`).
- User-facing text comes from `src/locales/<lang>/<namespace>.json` through i18next; English is the source, Korean the translation. Literal strings in JSX text and user-visible attributes fail `i18next/no-literal-string`. Keys are type-checked by `tsc`.
- Translation keys follow docs/15 §12: `<ns>:<area>.<element>`. A key without a prefix is looked up in `common` only, so keys of every other namespace are written with their prefix: `useTranslation(['common', 'xlog'])` and `t('xlog:summary.title')`, not `useTranslation('xlog')` and `t('summary.title')`. Pass the namespaces as an array: i18next's types accept a `<ns>:` prefix only then. `check:i18n` fails an unprefixed key that is not in `common` and says which prefix to use.
- `check:i18n` expects the catalogs of the languages in `src/i18n/resources.ts` (`--languages`, default `en,ko`; a test keeps the two in sync). A missing language directory or namespace file is a warning, and an error with `--release`.
- Untrusted strings reach the DOM only as React text nodes (SEC-60): `react/no-danger` on DOM elements and components, and `no-restricted-syntax` for `dangerouslySetInnerHTML` in any form (JSX attribute, spread or `createElement` props object, member access), `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `createContextualFragment`, `setHTML`/`setHTMLUnsafe`/`parseHTMLUnsafe`, `DOMParser`/`parseFromString`, `document.write`, `eval`, `Function`, `srcdoc` (JSX attribute or property) and `setAttribute` of `srcdoc` or `on*` event handler attributes.
- `fetch`/`XMLHttpRequest` only in `src/api`, `WebSocket` only in `src/realtime`, `EventSource` and `navigator.sendBeacon` nowhere (a beacon would POST without `X-Argos-CSRF`, SEC-43), Ant Design only in `src/components` and `src/app`, uPlot only in `src/charts`, the generated API types and `openapi-fetch` only in `src/api`, and `zod` only in `src/app` (everything else imports `z` from `src/app/zod.ts`, which turns zod's JIT off: zod 4 probes `new Function`, which the server CSP without `'unsafe-eval'` reports as a violation). This covers static imports (`no-restricted-imports`) and `import()` with a literal module name (`no-restricted-syntax`).
- Collected strings are typed `Untrusted` (branded, from `x-argos-untrusted` in the contract) and reach JSX only as `<SafeText value>`, `<CodeBlock value>` or `<SafeLink href>` (`argos/untrusted-text`, type-aware; templates, `String()`, string methods, member access on derived text such as `value.split('/')[0]`, calls that return text such as `JSON.stringify({ n: value })` or `Array.from(value).join('')`, `as` casts and i18n interpolation `t('key', { name: value })` are caught too). Checklist: [src/security/untrusted.md](src/security/untrusted.md).
- Link targets (`href` of DOM elements and Ant Design link components) are internal path literals or `safeHref(…)` (`argos/no-raw-href`).
- No `blob:` object URLs (`URL.createObjectURL`, `argos/no-object-url`): downloads go through `saveFile()` of `src/api/exportCsv.ts`, the one file exempt in `eslint-allow.json`.
- Browser storage holds preferences only: `localStorage`/`sessionStorage` with literal `argos.ui.*` keys, no cookie writes, no IndexedDB (`argos/no-token-storage`, SEC-40). The session lives in httpOnly cookies.
- Production code imports only packages listed in `dependencies`.
- Inline `eslint-disable` comments are ignored in `src/`. Exceptions are listed per file, with a reason, in `eslint-allow.json`.
- Bundled packages must be licensed under Apache-2.0, MIT, MIT-0, BSD-2-Clause, BSD-3-Clause, ISC, 0BSD, PostgreSQL, Unicode-DFS or CC0-1.0 (`scripts/license-policy.json`).
- The bundle never references another origin: no external `src`/`href`/`url()`/`@import`, and no absolute URL in any script, stylesheet or markup, also not escaped (`https:\/\/…`) or as a protocol-relative string (`"//host/…"`). Exact URL strings that are never fetched (XML namespaces, links in library error messages) are listed with a reason in `scripts/external-allowlist.json`; escaped URLs are matched in their unescaped form.

## URL state (docs/15 §4, DSN-14-17, ADR-0010 C-166)

`src/state/urlState.ts` parses and writes every shared state of a screen. The writer emits only the docs/14 §6 form (DSN-14-17): `from`/`to` (`now-15m`, `now/d`, ISO-8601 UTC), `kind`, `f.<field>=value` (equals; several values of one field mean "any of them"), `f.<field>=!value` (exclude; a value starting with `!` or `\` gets a leading `\`), `sel=ms:<min>-<max>,ts:<from>-<to>`, `live=1`, `kiosk=1`, `env`, `tab`, …

- Extension (PM decision pending): `f.<field>.<op>=value` with `op` = `gt`, `gte`, `lt`, `lte` or `contains` is a WO-30 extension of DSN-14-17 for column range and text filters (docs/15 §6.3). It is not part of the canonical grammar shared with the alert deep links (WO-25), and server deep links must not emit it until the PM decides. The UI writes it only for those operators.
- The reader also accepts the docs/15 §4.2 forms and normalises them: `range=<preset>`, epoch milliseconds, `f=<field>:<op>:<value>` (op `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `contains` or `in`; `f=status:in:500,503` becomes `f.status=500&f.status=503`), `sel=<t1>,<t2>,<y1>,<y2>`, `kind` in any case.
- Every item is validated on its own; an invalid one falls back to its default and shows `url-restore-notice` once. Limits: query ≤ 8 KB read, URL ≤ 2 KB written, ≤ 20 filters (each value of an `in` list counts), filter and search values ≤ 1,024 UTF-8 bytes like the server (`utf8ByteLength`, `fitsFilterValue`; 341 Hangul syllables fit, 342 do not).

## Adding a screen (WO-31..39)

1. Put the screen in `src/features/<screen>/<Screen>.tsx` and add one line to its entry in `src/routes/screens.ts`: `load: () => import('../features/<screen>/<Screen>').then((m) => m.<Screen>)`. Route, permission guard (`route-forbidden`), URL loader, side menu entry and `g` shortcuts already work; the placeholder disappears.
2. URL state: `useUrlState(<Schema>)` (`state`, `issues`, `set(partial, { replace?, pathname? })`, the only URL writer; 2 KB write limit). Screen keys extend `CommonQ` with the field helpers of `urlState.ts`. Time range: `useTimeRange()` (`range`, `live`, `liveAvailable` from the screen entry's `live` flag, `sel`, `resolved`, `queryRange`, `dispatch(action)`), REST refill after "resume live" with `useResumeResync`. Keyboard: `t` then `1`–`9` picks a preset (docs/15 §5).
3. Data: an API function in `src/api/<resource>.ts` (the generated types are importable only inside `src/api`), `unwrap(api().client.GET('/api/v1/…', …))` gives `{ data, meta }`; query keys from `queryKeys.screen('<screen>', { appId, range: time.queryRange, … })`. 64-bit ids stay strings (C-175). Show `meta.truncated`, `meta.retention_exceeded` and `meta.sampling` with `PartialBanner`, errors with `ErrorState` (`errorInfo(error)`), `null` values as `—` (never 0).
   Tables (common API of the screen work orders):
   - CSV: `exportCsv(method, path, request)` in `src/api/exportCsv.ts` from `DataTable`'s `onExportCsv`. It accepts only contract operations that answer `text/csv` (type-checked), sends `format=csv` (and `tz`, default the browser zone) through the shared transport (cookies, `X-Argos-CSRF` on POST, one refresh on 401) and saves the file under the sanitised Content-Disposition name. A 429 is an `ApiError` with `retryAfterSeconds`: show the retry hint, never retry in a loop (C-176). The UI never builds a CSV (DSN-15-06). Its `saveFile()` is the only place allowed to create object URLs (`argos/no-object-url`).
   - Sort: `sortSpecToUrl(sort)` / `urlToSortSpec(state.sort)` in `src/state/sort.ts` convert `DataTable`'s `{ id, desc }` to and from `sort=field:asc|desc`, the URL and API form.
   - Filters: `src/state/filters.ts` turns a `FilterChipBar`/`DataTable` filter (column filter, cell include/exclude) into URL state (field pattern, 1,024 UTF-8 bytes per value). `toUrlFilter(spec)` gives one filter (single filters only: an `in` list with one value becomes `eq`, a list with several values or an empty item gives `null`). `toUrlFilters(spec)` gives the list: `in` (`a,b`) expands to one `eq` per value with the same rule as the URL reader (`splitInList` in `urlState.ts`; `null` for an empty item, a value over 1,024 bytes or more than 20 values); keeping the total at or under 20 filters is the caller's job. Write the list with `useUrlState().set({ filters })`.
   - Cell include/exclude (`filterable` columns, `onCellFilter`): a column with `filterValue` uses only `filterValue(row)`; when it returns `null`/`undefined` that cell has no include/exclude (no buttons, no cell menu), and the shown value never stands in for the key under its `filterField`. A column without `filterValue` uses the shown `value(row)`. The value is passed as is and never cut. A value over 1,024 UTF-8 bytes (SEC-64) cannot be a filter: `cell-filter-include`/`cell-filter-exclude` and both items of the cell menu are disabled (`disabled`, `aria-disabled="true"`), say why in `title` and `aria-describedby`, and the menu shows `data-table-cell-too-long`; the keyboard path (Shift+F10, context menu key) behaves the same. For columns of long collected strings (SQL text, URLs, error messages), give a short key through `filterValue` (an id such as `sql_id`) with its `filterField`.
4. Live data: `useTopic(topic, params | null, { onData, onResync, onError })`; the shell already subscribes `counter` / `overview` and shows `ws-stale-badge`.
5. Strings: i18n keys only (`<ns>:<area>.<element>`, `en` and `ko`; new namespaces are registered in `src/i18n/resources.ts`). Collected strings only through `SafeText`, `SafeLink`, `CodeBlock`.
6. E2E: add `e2e/required/<screen>.yaml` (format in [e2e/README.md](e2e/README.md#required-elements-e2erequired)) and `defineRequiredTests('<screen>')` in `e2e/specs/required.spec.ts`; manifest variables (absolute range, representative ids, window totals) are in `e2e/required/variables.ts`.

## XLog canvas proof of concept (`/xlog-poc`, WO-04)

`corepack pnpm dev` (or `build` + `preview`) and open `/xlog-poc`. The page generates synthetic transactions in the browser (no server): 100,000 points with log-normal response times, Zipf-distributed services, skewed instances, an incident window, and XSS payloads in some service, instance and error class names (they must always render as text). The canvas lives in `src/xlog/` (`XLogBuffer`, `renderer`, `hitIndex`, `selectionSummary`, `engine`, `XLogCanvas`); the demo page in `src/features/xlog-poc/`.

URL parameters (invalid values fall back to the default):

| Parameter     | Values (default)                              | Meaning                                                                                                                                                   |

## End-to-end and performance tests (Playwright)

Playwright (`@playwright/test`, Apache-2.0, a devDependency) drives Chromium; the suites are separate from `test` because they need a browser and a build. Install the browser once per machine (it goes to the Playwright cache, `%LOCALAPPDATA%\ms-playwright` on Windows, `~/.cache/ms-playwright` on Linux):

```sh
corepack pnpm playwright:install      # = playwright install chromium (Linux CI: add --with-deps)
corepack pnpm e2e                     # vite build + E2E projects preview and stack
corepack pnpm e2e:docker              # stack project in the pinned Linux image (screenshot baselines)
corepack pnpm perf                    # vite build + XLog frame-time spec (about 12–16 minutes)
corepack pnpm perf:initial-load       # initial load against the stack (reference values)
```

**Stack E2E (WO-30, docs/18 §13).** The `stack` project runs every WO-30 spec against the server boot jar of this tree, with PostgreSQL and ClickHouse containers on random `127.0.0.1` ports (label `io.argos.e2e`, name prefix `argos-e2e-`, at most 5 GiB with the Playwright container, always removed). Build the jars first, from the repository root: `./gradlew :server:bootJar :agent:agent-dist:agentJar :sample-apps:shop-boot3:sampleAppJar :sample-apps:ext-stub:sampleAppJar :sample-apps:smoke:sampleAppJar` (the stack refuses a server jar older than the UI or server sources). It needs Docker, JDK 21 on `JAVA_HOME` and, on Windows, Git Bash. The seed is deterministic (generator seed 42, profile tiny, anchored on the current UTC day, C-170): `:server:loadQueryTestData` data and PostgreSQL metadata, three users (admin, operator, viewer), shop-boot3 with the agent and `test/seed/seed-traffic.sh` through gRPC. The seed manifest `ui/e2e/.stack/seed-manifest.json` gives the specs the absolute range, representative ids and window totals; specs assert exact values from it or from an API query, never "at least one". The WebSocket endpoint is the only stub (`page.routeWebSocket`, docs/14 §5, until WO-22). CSP (SEC-46, ADR-0010 C-188): every stack test fails on any `securitypolicyviolation` event under the server's nonce policy, in the page's current document (page hooks) and in every other document of its browser context, also one left by a navigation or another tab (`contextCsp` of `e2e/fixtures/stack.ts`); the positive controls in `e2e/specs/csp-report.spec.ts` cause a real violation on a stack page and must see it. Screenshot baselines (`e2e/specs/__screenshots__/`) are created and compared only in the pinned Linux image (`e2e:docker`); elsewhere those tests are skipped with the annotation `screenshot-linux-only`. Everything else (variables, projects, fixtures, required YAML, troubleshooting): [e2e/README.md](e2e/README.md).

The `preview` project and the frame-time suite serve `dist/` with `vite preview` on `127.0.0.1:4319` (`ARGOS_UI_PORT` changes the port). The preview sends the Content-Security-Policy of docs/16 §9.9 (SEC-46) without its nonce and report parts (`preview.headers` in `vite.config.ts`; the dev server sends none). `ARGOS_UI_BASE_URL=http://host:port` runs them against a server that is already running instead (for example `corepack pnpm dev`), without starting one. Viewport 1366×768, locale `en-US`, Chromium in new headless mode (`channel: 'chromium'`). The E2E suite runs at devicePixelRatio 1; the performance spec runs every scenario at each ratio of `XLOG_PERF_DPR` (default 1 and 2).

The `e2e`, `e2e:preview` and `perf` scripts build first; the suites themselves serve `dist/` as it is (the `stack` project serves the UI from the server boot jar instead). When you run `corepack pnpm exec playwright test` directly, run `corepack pnpm build` first: the global setups (`e2e/fixtures/globalSetup.ts`, `perf/lib/globalSetup.ts`) fail when `dist/index.html` is missing or older than the newest file of `src/`, `index.html`, `vite.config.ts` or `package.json` (not checked with `ARGOS_UI_BASE_URL`).

- **E2E** (`playwright.config.ts`, `e2e/specs/<screen>.spec.ts`, docs/18 §13): no retries, one worker, trace and screenshot only on failure (`test-results/e2e`, HTML report in `playwright-report/e2e`). `e2e/fixtures/fixtures.ts` checks after every test that `window.__xss` is undefined and that no dialog, page error, console error, CSP violation or request to another origin happened. The fixture option `ignoredConsoleErrors` (regular expressions, default none, `test.use({ ignoredConsoleErrors: [...] })`) exempts matching console errors; it is meant for positive controls only, and each exempted message is listed in an `ignored-console-error` annotation. With the suite's own preview the fixture also requires a `Content-Security-Policy` header on every main-frame document, so "no CSP violation" is checked under the preview policy; against `ARGOS_UI_BASE_URL` the header is not required and the test gets a `csp-not-verified` annotation. `e2e/specs/global-hooks.spec.ts` holds the positive controls: an injected inline script must be blocked and recorded as a violation, and the hook check must reject it. Chrome also logs the blocked script as a console error, so the controls exempt exactly that message: one test checks that, with the exemption, the recorded violation is the only failing check (clearing it makes the check pass), and the fixture-level control (`test.fail()`) therefore fails only through the fixture's CSP violation check — if the fixture stopped checking violations, that test would pass and Playwright would report it. Console errors the option does not match must still be rejected, and a document without the header must be rejected. The positive controls open `/xlog-poc` (the shell at `/` needs the server nonce, which `vite preview` does not inject). `xlog-poc.spec.ts` drags on `/xlog-poc` and compares the selection summary and list with the expected points, which `e2e/fixtures/xlogOracle.ts` computes from the same seeded generator in Node.
- **Performance** (`playwright.perf.config.ts`, `perf/xlog-frame.spec.ts`): static 10k/50k/100k points (consecutive full redraws), static 100k with the slowest configuration (y = log, colour = service), realtime 100k + 500 points/s, hover/drag over 100k points (plus a second, not judged trace around the end of the drag), and 100k full-plot drag selections (selection, summary and React commit times, not judged here; the ADR-0003 C-36 budgets for them are judged in WO-33). Every scenario runs at each devicePixelRatio of `XLOG_PERF_DPR` (default 1 and 2; titles carry `dpr=<n>`). Each scenario warms up and measures at least 3 runs; before each run it samples the machine CPU load and waits up to `XLOG_PERF_MAX_WAIT` seconds for it to drop to `XLOG_PERF_MAX_LOAD` %. The per-frame time is the busiest rendering-pipeline thread (renderer main, compositor, GPU main, display compositor) per frame in a Chrome trace (`perf/lib/frames.ts`); the spec passes a scenario when the p95 and the mean of the frames of all its runs together are at most 16 ms. ADR-0003 C-35 judges each run instead (pooled values are for reporting); read that verdict from the summary table's highest single-run p95 and mean (`Max run p95`, `Max run mean`), which must both be at most 16 ms. A run whose trace lacks the renderer main thread or the GPU thread (`CrGpuMain`, or `Chrome_InProcGpuThread` with an in-process GPU), or in which Chrome reported trace data loss, fails a judged scenario whatever its numbers (`measurementProblems` in `perf/lib/frames.ts`). Results: `perf/results/xlog-frame-<time>.{jsonl,json,md}` and `xlog-frame-latest.*` (git-ignored). Settings (environment variables, see `perf/lib/settings.ts`): `XLOG_PERF_POINTS`, `XLOG_PERF_RENDER` (`default`, `path`, `rect`, `pixels`), `XLOG_PERF_SCENARIOS`, `XLOG_PERF_DPR`, `XLOG_PERF_COLOR`, `XLOG_PERF_Y`, `XLOG_PERF_POINT_CAP`, `XLOG_PERF_RUNS` (≥ 3), `XLOG_PERF_FRAMES`, `XLOG_PERF_LIVE_SECONDS`, `XLOG_PERF_MAX_LOAD`, `XLOG_PERF_MAX_WAIT`, `XLOG_PERF_COMPARE=1` (adds a realtime run with `incremental=0`, not judged), `XLOG_PERF_HEADED=1`, `XLOG_PERF_OUT`, `XLOG_PERF_EXPECT_GPU` (a case-insensitive part of the WebGL renderer string, e.g. `Radeon`: a run on another GPU fails the judged scenarios; hybrid-GPU laptops can switch between the integrated and the discrete GPU). Method and results: [docs/poc/xlog-ui.md](../docs/poc/xlog-ui.md).
